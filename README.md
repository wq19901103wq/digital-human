# Digital Human · 对抗式文字数字人迭代框架

让 AI 生成器在**盲测对抗**中迭代得越来越像真人。系统围绕一个唯一优化目标运转：
**盲测 Judge 在固定测试题上把 AI 回复识别为 AI 的比例（越低越像人）**。
生成器与 Judge 交替升级，每轮只改一个方向，改动必须可证伪，任何结论可从冻结证据逐题重算。

这不是一个"调用大模型写回复"的壳子——它是一套**证据优先、统计纪律严明、防刷防作弊**的迭代操作系统。

## 技术架构总览

自下而上四层：版本层是底座，证据层承载原始逐题记录，测量库由证据层**派生**，
迭代引擎在顶层消费三者。（逻辑分层与物理实现解耦：测量库代码位于
`src/iteration/measurements.py`，但逻辑上是独立派生层。）

```
┌─────────────────────────────────────────────────────────────────────┐
│ 迭代引擎层                                                            │
│   runner（断点续跑/并行/翻转补验）  gates（三道晋升门槛）             │
│   promote（指针晋升）  branches（多分支异步调度）                     │
│   learning_guard 学习护栏（来源隔离：时间窗口/资产指纹/运行时封印）   │
├─────────────────────────────────────────────────────────────────────┤
│ 按侧测量库（派生层，可删可重建）                                      │
│   judge 对每侧的判定是"该侧回复 vs 固定真人回复"的绝对测量            │
│   → 测量按 (版本, 题, 轮次) 入库：同条件对比零成本复现               │
│   → 四指纹（side/judge/pair/round）硬约束复用条件                    │
│   → 同对整轮重放零调用；补轮只跑缺的题；判决一律回读证据层原文重算    │
├─────────────────────────────────────────────────────────────────────┤
│ 证据层（experiments/<id>/，唯一权威）                                 │
│   cases.jsonl  逐题证据（append-only，record_contract 守门）          │
│   traces/      调用实录（提示词/响应/耗时全留痕）                     │
│   spec.json    冻结输入快照：版本引用 + 协议超参 + 材料指纹           │
│   原则：证据与结论分离；结论永远从证据重算，不信任任何汇总数字          │
├─────────────────────────────────────────────────────────────────────┤
│ 版本层（write-once，目录即版本）                                      │
│   data d-XXXX（切分+池+用途清单）  generator g-XXXX  judge j-XXXX    │
│   pointers.json 五指针：data / production_gen / iteration_gen /       │
│   production_judge / iteration_judge；晋升=切指针，无拷贝无二状态      │
└─────────────────────────────────────────────────────────────────────┘
```

### 一、证据优先：结论永远可以从冻结证据重算

系统的信任建立在一条铁律上：**cases.jsonl 及其哈希链是唯一权威证据**。

- 实验的"输入"（spec：版本引用、协议超参快照、材料指纹）与"逐题证据"（cases.jsonl）
  与"结论"（state 中的指标/裁决）三层分离；
- `finish()` 写入的汇总指标只是缓存——任何晋升判决（`gates.confirmed_metrics`）都
  **逐题重读 cases.jsonl 重算**，与写入值不一致即拒绝；
- 测量库（派生层）可以删、可以重建：每条测量带回源（实验、行号），判决使用前必须
  **回读证据层原文行、重算全部指纹、逐字段比对**——篡改派生层在物理上无效；
- 调用实录（traces/）保留每次大模型调用的完整提示词、响应正文、耗时与用量，
  修 scorer、修 bug、事后审计都有据可查。

### 二、统计纪律：配对补验与"确认净胜"

judge 是噪声仪器（实测相邻两次独立判定翻转率约 1/3），所以初测只是描述值：

- 初测分歧的题，两侧各做 N 轮**独立重新判定**，按多数票出"最终判定"；
- 门槛指标是**确认净胜**（补验后胜题−负题，打平计 contested 不计），
  而非识别数之差；晋升线按冻结协议的比率计算（如 +5/1000）；
- **按侧测量可复用的统计边界**是显式设计对象：同一实验内配对同测的两侧正相关
  （共变噪声抵消，净胜方差更小）；跨实验拼侧复用必须由历史数据先做方差膨胀
  验证（设计文档 §9 P0），验证不通过就不放行——复用不改变任何统计口径。

### 三、防刷与防 p-hacking

- **固定批次一次性**：固定验收题分配即消耗、one-shot；开发轮用不限量开发集随便试，
  攒够证据才动固定集；
- **取票规则机械化**：补验票固定为协议数量、按独立轮次指纹去重、按时间取最早凑足、
  禁止按结果挑选，全程写入凭证可复现；
- **指纹全字段枚举**：换 judge 权重/提示词、数据版本变化、协议参数变化，指纹必变，
  物理上不可能跨条件复用测量；
- **晋升三道门槛**（前置开发阶段免费，不计入把关）：固定准入（同条件直接对比
  生产）→ 固定验收（消耗一次性批次）→ 推全（原子切指针 + 凭证）。

### 四、数据边界：时间窗口与泄漏防护

- 全局时间窗口（schema 2）：学习 / 开发 / 验收按每题输入时刻过滤；
  学习材料必须早于截止时间且通过来源指纹核验；
- 整聊天留出（whole-chat holdout）：未见对象的独立验收条件；
- 引用消息保留：群聊引用（quote）类型消息带实质内容，导入时保留
  （防止假时间断层导致上下文被静默截短）；
- 学习护栏（learning_guard）：静态资产的时间边界、资产文件哈希、`learning.json`
  来源证明，全部运行时强制。

### 五、多分支异步迭代

分支调度器（`iterate_branches`）支持多个改进方向并行：每个分支基于生产基线提交
单一改动，独立冒烟 → 开发 → 保留开发版 / 固定准入 → 固定验收 → 推全；推全前自动
核对生产三指针未前进，过期分支作废重测。`stage_limit` 可把分支限制在"只跑开发"，
界面会明示挡板与解除命令。

## 实验协议（一条候选的完整旅程）

```
submit（冻结提案：一个改动 + stage_limit）
  → 冒烟（2 题接线，不进结论）
  → 开发（完整开发集，确认净胜 > 0 = 达标；免费）
  → 固定准入（同一候选 vs 当前生产，直接对比，净胜 ≥ 线；免费）
  → 固定验收（生产 vs 候选锁定快照，固定批次，识别数严格改善且净胜 ≥ 线）
  → 推全（指针原子切换 + 凭证；其他分支基于新全量重测）
```

概念分层：**达标**是测量结论（指针不动）；**已晋升**只指指针切换/推全凭证（硬证据）。

## 5 分钟跑通（冒烟）

```bash
pip install -r requirements.txt
cp examples/chat_export.sample.jsonl data/chat_export.jsonl   # 合成示例数据
export DH_LLM_BASE_URL=<你的 OpenAI 兼容端点> DH_LLM_API_KEY=<你的密钥>

python scripts/bootstrap.py --data data/chat_export.jsonl --model <生成模型>
python scripts/run.py --dataset development --change "冒烟接线验证" --limit 2
python scripts/serve_dashboard.py --port 8080   # http://localhost:8080/dashboard/
```

## 目录

| 路径 | 职责 |
|---|---|
| `src/iteration/` | 迭代引擎：runner / gates / promote / branches / learning_guard / **measurements（按侧测量库）** |
| `src/judge/` | 盲测裁判：配对判定、特征抽取、冻结校正模型（LR/GBDT）、mode 兼容 |
| `src/generator/` | 人格提示词 + 场景规则 + few-shot 召回（策略冻结）+ 学习示例选择 |
| `src/bootstrap/` | 数据构建：ingest（引用消息保留）/ 切分 / 池 / 用途清单 / 时间窗口 |
| `src/dashboard/` | 工作台：基线与分支基线视图、四维筛选、逐题证据与调用实录、实时进度 |
| `scripts/` | 命令入口（run/promote/iterate_branches/check.py 统一校验/export_public 导出） |
| `docs/` | SOP、架构、数据契约、测量库设计（含完整评审记录） |
| `tests/` | 回归测试（可选重依赖 torch/xgboost 缺失时自动跳过） |

## 校验门禁

- `python scripts/check.py code` —— 统一校验入口，聚合规则 / 文档 / 公开边界 /
  回归 / 离线 demo（CI 跑的就是它）；
- `scripts/check_public.py --history` —— 公开边界扫描也可独立运行：内容模式 +
  路径黑名单 + 阻断词 + src 依赖方向 + **git 提交元数据与全历史**，fail-closed；
- 版本 write-once、指针白名单写入、cases.jsonl 只能经 record_contract.writer——
  均为 AST 级强制（`scripts/check_rules.py`）。
