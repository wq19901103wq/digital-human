# 实验结果与请求缓存

实现入口：[cache.py](../src/cache.py)。数据库位于每个实例的
`instances/<instance>/.cache/results.sqlite3`，实验实录继续保存在原目录。

核心原则：**实验 ID、数据版本 ID 用于查来源，实际输入和执行依赖决定能否复用。**
相同版本名不代表输入未变；不同版本名也可能对应完全相同的输入。

## 分层及取舍

| 层级 | 当前处理 | 能省掉什么 / 何时失效 |
| --- | --- | --- |
| 数据快照、冻结评估包 | 创建时绑定内容指纹，续跑前核验 | 样本、参考答案、启用的 few-shot 池或冻结包变化时阻止旧断点复用；生成器推全后仍用原题重建回复 |
| 实验、逐题结果历史 | 统一查询索引；成功断点先验数据 | 按实验 ID、题目 ID、数据版本和绑定版本查历史；数据指纹一致时跳过成功题，失败或中断部分继续补齐 |
| 生成回复 `generation` | 已接入 | 完整提示词、有效模型配置、强制回复约束、解析实现相同，复用已校验回复 |
| 最终单轮判定 `judge` | 已接入 | 上下文、真人/AI 回复、Judge 配置及冻结资产、实现相同，复用该轮判定 |
| 大模型初判 `judge_initial` | 已接入来源裁判 | 完整盲测提示词、初判模型、解析实现相同，可独立于后续特征提取和校正复用 |
| 特征抽取与解析 `judge_features` | 已接入 | 昂贵的特征抽取由请求层复用；解析结果按原始响应和解析实现复用 |
| 原始 LLM 请求 `llm_request` | 已接入 API 与 Codex CLI 适配器 | 按实际完整请求体/提示词、输出 schema、模型与有效配置复用通过调用方校验的响应 |
| 盲测顺序 `blind_order` | 已持久化 | 同一 Judge/题/轮次中断后保留已分配的 A/B 顺序，让完成的初判仍可复用 |
| 并发中的相同任务 | 已接入逐键线程/进程锁 | 一份计算执行，其他调用等待后读结果；不同键仍可并行 |
| few-shot 召回、提示词组装 | 暂不新增缓存 | 目前仍执行本地计算，再用最终提示词查生成缓存；若将来成为瓶颈，键需含池内容、检索实现、查询、排除样本和预算 |
| 特征矩阵、训练产物 | 当前训练链路未接入 | 当前 LR 为冻结资产，不会每轮重训；将来真有训练任务时，键需含样本/标签/划分、特征定义、算法、超参和随机种子 |
| 汇总、比较与采用决定 | 汇总保留历史，每次按当前实验重新计算 | 逐题结果可复用，但不能把旧实验的“通过/推全”直接当作新基线上的结论 |

对跨实验最有用的是“生成 → 初判/特征 → 单轮判定”分层。只改 Judge 时，已有
AI 回复无需重生成；只改特征模型时，输入相同的初判仍可复用；只改校正阈值时，
相同盲测输入下的初判和特征请求可复用，最终判定重新计算。

不同 Judge 配置仍按原机制各自随机换位，因此改配置后可能得到不同 A/B 顺序，
这时对应提示词确实不同，需要计算。没有为提高命中率而改变盲测抽样规则。

## 缓存键与失效

每个键包含：缓存格式版本、层级、该层真实输入/依赖、数据分区、题目 ID、轮次、
采样批次 `sample_epoch` 和全局失效代号 `DH_CACHE_EPOCH`。

- API 身份包含协议、地址指纹、模型、temperature、max_tokens、可选 model_revision
  和适配器代码指纹；精确请求体还包括 messages 和输出格式。
- Codex CLI 身份包含通道、模型、reasoning_effort、CLI 版本、可选 model_revision
  和适配器代码指纹；请求包含完整提示词与输出 schema。
- Judge 上层键还包括冻结资产/权重/阈值及推理代码指纹。生成上层键使用最终提示词，
  因此池或模板变化且实际输入改变时会失效。
- 实验 ID、baseline/candidate 角色、版本别名不进入开发集计算身份；它们存入来源。
  这样 A 实验的候选推全后成为 B 实验的基线，相同计算仍能命中。
- 不跨实例共享；固定集及未知分区还按实验 ID 隔离。缓存不绕过准入、样本冻结、
  one-shot 或推全检查。
- 不做语义相似缓存；改一个真正影响输入的字段也要重新查键。

模型别名背后的服务端版本无法仅凭字符串自动识别。已知远端升级时，可在新任务中
设置新的 `DH_CACHE_EPOCH`，或在模型配置中声明 `model_revision`，保留旧缓存但不再命中。

## 数据变更与中断续跑

续跑保护入口：[data_guard.py](../src/iteration/data_guard.py)。实验 ID 和
`case_id` 只定位历史记录，不能单独证明旧结果适用于当前输入。

- 新生成实验（包括并行分支）在创建时保存实际样本内容和顺序的指纹，覆盖上下文、
  真人答案及样本元信息。启用检索时，还绑定 `fewshot_pool.jsonl` 内容和审批条件。
  关闭检索的池、另一数据分区、JSON 键顺序或空行变化不影响本轮续跑。
- 新 Judge 实验在创建时保存完整评估包 SHA。同题的 AI 回复、真人回复、上下文、
  样本增删或顺序改变，都会在评分前被拦截。重建 Judge 包也核验原题及检索池依赖。
- 首次执行还原子保存 `data_snapshot.json`，此后先校验，再跳过成功题。校验失败不
  删除或覆盖原断点，不产生新模型请求，也不把变更前后的结果合并为一次评测。
  恢复原始数据后，可以继续复用成功断点，仅补失败或中断部分。
- 同一实验仍遵守原来的冻结样本规则。确需更改数据，应创建新数据版本和符合既有
  准入规则的新实验；底层缓存按实际输入和依赖复用未受影响的计算，不复用旧采用结论。

旧任务尚无结果或实录时，可在首次启动建立指纹；已有完整冻结包 SHA 的旧 Judge
任务可以据此续跑。**旧断点没有可验证的数据指纹时，会保留并拒绝直接复用**，不会
事后拿当前文件补签为旧结果的来源。只有历史题目 ID/上下文不足以证明所有依赖未变。
已完赛任务仍显示其历史报告，不会因外部数据文件变化被自动重评。

## 复用与独立采样

默认仅在 `CaseTrace.operation` 中启用，在线聊天和未追踪调用仍直接执行。
新启动的评测自动接入；已运行并加载旧代码的进程不会被自动重启或切换。

初测 `round=0` 和两次补测 `round=1,2` 各有独立键。即使提示词相同，三轮仍产生
三份独立调用；另一实验复用的是同轮已保存的样本，不会把一次响应复制成三票。
相同文字但不同题目 ID 也不会被合并成同一次随机样本。

`CaseTrace` 接收的规格支持 `cache: {enabled: false}` 或
`cache: {sample_epoch: "独立研究批次"}`，默认启用且批次为 `shared-v1`。
这是程序接口，现有运行命令未另加缓存参数。若要独立重抽样，应在新任务创建时指定
新批次；不要修改正在执行的实验规格。轮次、批次和失效代号均保存在实录/索引中。

命中代表复用了历史观测，不能作为“又多跑了一次独立验证”的证据。报告的生成耗时
是当前调用耗时（命中时含读缓存），不能混用来比较模型本身的推理延迟；原调用实录
仍保留原始耗时及 token 用量。

## 完整性、失败与追溯

SQLite 保存完整请求身份、成功结果、内容校验和、首次来源及后续使用关系。
每个缓存键单独加锁，网络调用期间不持有数据库写事务。首次建库也有进程锁。

异常、截断、拒答、空文本及调用方判定为非法的响应不进入成功结果缓存。
若特征抽取失败，已完成的初判和盲测顺序可以保留，下次只补失败部分。
进程退出后由系统释放锁。不能承诺外部 API 的 exactly-once：如果远端已返回但本地
尚未持久化就崩溃，该次结果无法复用，仍可能重发。

缓存文件内容校验失败会报错，不静默当成有效答案。查询索引写入失败时，原始实录
继续保留，并记录告警，可重新建立索引，不覆盖原始调用异常。

逐题详情显示“缓存复用（本步骤未重新计算）”及来源实验、实录和键。
认证密钥不进入缓存身份；缓存目录（含经符号链接访问）不能通过后台静态文件接口下载。

## 查询

以下命令只读历史/缓存或更新本地查询索引，不发起模型请求。

```bash
python scripts/cache_results.py --instance example-agent index
python scripts/cache_results.py --instance example-agent stats
python scripts/cache_results.py --instance example-agent history --experiment EXP_ID --case-id CASE_ID
python scripts/cache_results.py --instance example-agent history --data-ref d-0003 --version j-0005 --limit 20
python scripts/cache_results.py --instance example-agent entries --layer llm_request --model MODEL_ID
python scripts/cache_results.py --instance example-agent get FULL_CACHE_KEY
```

`history --version` 匹配实验绑定的任意版本（基线/候选/裁判等），不是只筛该版本
亲自产出的那一侧；具体看返回的 branch、kind 和 versions。`entries` 也支持
`--experiment`、`--case-id`。上层命中时不伪造下层调用；下层请求记录在原始实验，
可沿 `cache_hits.origin` 查回。`get` 返回完整请求身份、响应与来源。

`index` 幂等导入旧实验摘要、逐题历史和调用实录，并保留失败及重试记录；新调用
会实时索引操作结果。实验摘要及 cases.jsonl 的最新快照可再次运行 `index` 导入。

**旧记录可查询不等于可自动复用。** 旧实录缺少完整地址/运行配置等身份时，只建
历史索引，不反推、补造可复用键。逐题断点和冻结包按上述数据指纹检查后复用。
