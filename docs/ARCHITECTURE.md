# 框架架构

框架负责执行和证明一次实验；实例决定研究谁、用哪些数据、改什么模型以及接受什么成本。候选方向由人提出。

## 模块职责

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `scripts/` | 参数解析、选择实例、调用服务、打印结果 | 训练循环、数据边界、采用规则 |
| `bootstrap/history.py` | 从原始消息构建历史样例和用途清单 | 根据模型得分挑选验收题 |
| `generator/` | 人格和场景、按题目时间检索、生成回复 | 选择生产版本、修改训练标签 |
| `judge/` | 盲测、特征抽取、LR 拟合与预测 | 决定候选是否发布 |
| `iteration/training.py` | 人工方案到有独立证据的候选 | 自动发明方案、自动选择训练臂 |
| `iteration/training_operations.py` | 训练生成和抽特征；共用断点、重试和计数循环 | 证明自己的结果正确 |
| `iteration/branch_packs.py` | 首次开发包、换生成器后的重建、绑定批次的验收包 | 提前生成整份固定验收池 |
| `iteration/experiment.py`、`runner.py` | 冻结实验、执行配对评估、统计并保存结果 | 因结果不佳偷偷换对照或样本 |
| `iteration/branches.py`、`scheduler.py` | 分支推进、重测、进程调度 | 把失效运行快照当作可恢复任务 |
| `iteration/protocol.py`、`gates.py`、`promote.py` | 计算结论、检查准入证据、条件更新指针 | 生成回复和训练特征 |
| `iteration/baseline.py` | 显式初始化或迁移兼容的基线组合 | 声称迁移带来效果提升 |
| `dashboard/` | 只读展示、实时状态、派生报告和访问路由 | 决定晋升、修补源数据 |

普通调用方向为 `scripts → iteration → generator/judge`；`dashboard` 读取已保存的规格和结果。`runner` 完成后调用 `dashboard.report.publish` 生成派生报告，这是执行边界上的输出步骤。业务对象不会导入命令脚本；页面组件不会反向导入执行器。

## 公共机制只保留一个入口

- `config.parse_overrides`：Gen/Judge 共用点路径参数解析，保留布尔、数字、列表等 JSON 类型。
- `storage.read_json/write_json/write_once_json`：缺失、损坏、可变写入与不可变创建的语义明确区分。普通 JSON 写入不会偷偷冻结运行环境。
- `experiment.write_spec`：显式冻结运行环境，再保存实验规格。规格已经存在时只能接受相同内容。
- `jobs`：统一映射任务目录、读取运行状态、判定活跃进程和已完成结果。调度器与后台共用这个视图。
- `task_state`：生产者的阶段和进程身份；`progress`：实验内部逐题并发、耗时和 trace。
- `datasets.pack_cases`：去掉生成字段，还原回复包的原始题目；生产者和校验入口无需互相导入。
- `dashboard.components`：HTML 转义、链接和小组件。实例页、版本页和流程页共用。

`state.json` 与 `scheduling/*.json` 不是两份相同状态：前者记录工作进度和结果，后者记录调度尝试、进程身份及退出情况。`jobs.snapshot` 派生统一视图，不为了显示一致而改写旧记录。

## 校验为何保留独立实现

`history_sources` 重建原始消息；`data_guard` 绑定题目和池；`learning_guard` 约束材料、调用和恢复；`training_evidence` 独立重建训练矩阵并重新拟合权重。

训练执行和来源审计可以共享文件读写、字段定义、目录解析，但不共用“直接相信训练结果”的捷径。特别是标签重建、实际请求核对和独立拟合，保留独立路径，防止同一错误同时通过生成和检查。

## 数据、执行与展示

```text
可信导入消息 → 数据版本及用途清单 → 人工提案
                                  ↓
                           冻结代码、环境和设置
                                  ↓
                    预检 → 生成 → 抽特征 → 拟合
                                  ↓
                            独立来源审计
                                  ↓
              候选 → 开发 → 当前生产基线对比 → 固定批次
                                                        ↓
                                                  条件更新指针

规格、进度、结果 ─────────────────────────→ 后台与报告
```

具体文件和唯一事实来源见 [数据模型](DATA_MODEL.md)，执行条件见 [实验规则](SOP.md)。

## 保持简单的边界

当前是单机文件系统框架：每个工作进程只处理一个实例，实例内使用文件锁，题目并发使用线程。不把 `versions.switch_instance` 当作多租户线程切换接口，也不承诺跨机器调度或对象存储锁。

运行快照保存代码和环境指纹，没有复制一整个虚拟环境。解释器或依赖版本变化时拒绝继续，需恢复原环境。对已有任务使用冻结执行器，对改过的行为创建新任务。

较大的 `few_shot.py` 和 `corrected_v1.py` 包含检索规则及有历史语义的特征实现，暂时保留。拆分它们需要证明召回排序、向量顺序和旧权重解释不变；按文件长度机械拆分收益有限。

当前 Gen“训练”是学习材料、提示词、检索及配置迭代；没有基础生成模型的梯度微调。Judge 流程会调用特征模型并训练本地 LR。扩展新的训练算法时，应新增明确的材料/产物契约和独立验证器，而不是复用 LR 名称保存另一种模型。
