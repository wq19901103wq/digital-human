# 数据边界 schema 2

2026-09-14，依据已确认的数据边界方案实施。新数据为 `d-0011`，现有生产组合保持 `d-0009 / g-0017 / j-0012`。旧版本和实验未迁移或重写。

## 已接入的边界

- 历史消息、全量候选示例、用途清单分开保存；数据中不再附带生成器提示词。
- 完整示例保存上下文及全部回复的稳定消息身份、起止范围和输入截止点。主线检索及新 Judge 训练入口先过滤可见历史，再匹配、排序。
- 未来回复、目标答案、留出聊天、来源或标签范围不明的示例不能进入当前生成；校验异常不能降级绕过。
- Gen 学习材料、Gen 优化题、Judge 训练题、Gen/Judge 开发验证和固定验收有独立用途清单和哈希。Gen/Judge 共用开发样本的情况明确展示。
- 无行为改动的生成器构建复用版本，来源单独留痕；新数据构建与已有实例的导入不再隐式切模型基线。
- 新数据可通过 `run.py --data` 与当前模型比较，不需要先改生产指针。实验和续跑校验题单、协议、运行实现、数据指纹。
- 新固定批次只能锁定给一个实验；来源不明的旧模型只能做开发诊断，不能消耗独立验收或晋升。
- 页面展示用途、真实样本、时间边界、训练任务、四类场景分数和已准备但未采用的数据。完整历史文件不能通过静态 URL 绕过封存答案规则。

全局窗口使用冻结时间戳 `1617358913` 和 `1700541286`。候选边界按完整历史样本的 25%/65% 位置确定，随后验证真实容量；不依据模型输出选时间或选题。

开发和固定各包含 600 道熟悉群聊、200 道熟悉私聊、150 道未见群聊、50 道未见私聊。未见条件是整聊天留出，不是自然首次接触；其聊天不会进入学习清单，回放该条件时也不会召回其历史。留出对象按聊天类型分层，并仅依据时间覆盖和容量做确定性筛选。

最初 50%/75% 时间窗口不满足每聊天最多 25 题下的评测容量；随机留出的未见群聊曾只有 115 题。因此没有直接使用默认窗口或补入熟悉题。Gen 优化与 Judge 拟合属于训练用途，每聊天最多 125 题；开发/固定仍最多 25 题。

两套各 1,000 题且完整片段独立的开发材料容量紧张，当前明确采用共用开发验证。它们用于选择候选，不声称是两次独立泛化证据。固定验收仍单独隔离。

## 入口

仅审计拟定数据容量：

```sh
python -B scripts/prepare_history.py --instance example-agent --exports /path/to/exports
```

加 `--build` 创建新数据版本，始终不切指针、不训练、不调用模型。也可用 `--development-start`、`--acceptance-start` 指定全局时间戳；容量不足直接报错。

完整核验已冻结数据的来源、正文、片段、时间和用途交集：

```sh
python -B scripts/legacy/audit_history.py --instance example-agent --data d-0011
```

在新数据上创建连接检查，基线仍取当前开发生成器：

```sh
python -B scripts/run.py --instance example-agent --data d-0011 --dataset development \
  --change "新历史边界接线验证" --limit 2 --create-only
```

调整生成器策略时增加 `--purpose gen_optimization`，使用 Gen 优化题清单。这类结果明确禁止晋升；选定候选后另用 `development` 验证。

新 Judge 训练入口默认只冻结任务与来源，使用显式的 Gen/Judge 配置：

```sh
python -B scripts/legacy/train_history_judge.py --instance example-agent --data d-0011 \
  --generator g-0017 --judge j-0012 --study my-history-training
```

`--preflight` 验证群聊和私聊各一题；`--run` 先预检再完成 1,200 题生成、特征提取与 LR 拟合，创建候选但不采用；再加 `--evaluate` 用冻结开发题单比较当前 Judge 与训练候选。已成功的结果可续跑复用，输入变化拒绝复用。使用项目既有训练虚拟环境，避免系统 Anaconda 的 NumPy/SciPy 不兼容。
