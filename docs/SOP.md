# digital-human 对抗迭代 SOP（唯一权威流程）

状态：现行。本文只规定**关键约束和合法步骤**；文件格式、状态机、校验细节见
`docs/IMPLEMENTATION.md`，行为约定见测试。本文未覆盖的情况：**停止执行并询问**。

## 总原则

0. **实例隔离**：每个数字人（如 example-agent / example-operator）是独立实例
   `instances/<名字>/`，版本、指针、实验、池完全隔离；机制层与超参全局共享。
   切换：`--instance <名字>` 或环境变量 `DH_INSTANCE`（默认 `default`）。
   实例内保留生产/开发双指针（§3），多方向并行使用独立分支（§6）；测试入口 = 冒烟 + 开发实验。

1. 唯一优化目标：Judge 盲测识别率（越低越像人）；其他质量维度暂不进指标。
2. **每份状态只有一个权威位置**：版本内容（不可变目录，创建后 chmod 只读，代码强制）、
   指针及采用凭证（pointers.json）、实验状态（experiments/<id>/state.json）、
   分支提案/轮次（branches/<name>/）。禁止手工编辑。
3. 交替冻结：每个实验内改生成器冻结 Judge，改 Judge 冻结生成器（以实验输入快照为准）。
   不同分支可并行，推全前核对完整生产基线。
4. 每轮唯一改动：候选 = 基线 + 一个 feature；改动描述必须可证伪。
5. 超参（`config/settings.yaml`）与版本配置分离；前者改动 = 协议变更。
6. **先划分数据，再学习数据特征**（split-first）。

## §1 数据与版本

**schema 2 新入口优先规则（2026-09-14）：**完整规则见 DATA_CONTRACT 的 schema 2 条款。
全量历史候选库按每题输入时刻过滤，不再按整个测试聊天删除历史。Gen 学习/优化、Judge 拟合、
开发选择和固定验收分别保存用途清单，采用全局时间窗口；熟悉时间回放与整聊天留出分层报告。
开发材料可显式共用，不作为两次独立验证；学习和开发的完整片段不得进入同批独立验收。
固定批次在创建实验时锁定，已使用批次恢复原实验，下一轮独立验收使用新批次。
静态模型/提示词的学习来源未知时，允许开发诊断，禁止消耗新验收批次或晋升。
数据准备不自动改变模型与生产组合；无行为变化的检查复用 g，构建来源单独记录。
以下旧三分区条款继续解释历史 schema 1，不用于重写旧数据或给旧模型补签来源认证。

1. **三分区**（bootstrap 按会话整块切出，seed 固定）：fixed 只评测、禁一切学习训练；
   dev 是开发材料（A/B 评测 + Judge 校准包）；train 供人格/场景/few-shot 池。
2. **版本即目录、创建后只读**：数据版本（切分+池+manifest）、生成器版本（行为配置+
   persona/场景自包含快照）、Judge 版本（配对盲测配置）。候选创建即得普通版本号，
   晋升只切指针。
3. 数据变更 = bootstrap 新建数据版本；`--adopt` 才切换指针并重建快照版本。
   旧版本原地保留，历史实验可复现。
4. few-shot 池小于 settings 的 `evaluation.pool_min_total` 禁止正式迭代；池审批（approved + 内容 hash）运行时强制。
5. **检索策略冻结**：只保留已验证的一条（处境匹配 + 词项 + 最新一句形式偏好仅私聊），
   来源过滤/逐题排除/预算控制保留；再引入新策略须先按 §2 开发集验证。

## §2 实验与恢复

1. 主线五步：**准备数据 → 创建候选 → 开发盲测 → 固定测试 → 晋升**。
   单线入口 `run.py`，分支调度入口 `iterate_branches.py`（§6），共用评分执行器与晋升门槛。
   新建实验自动完成预检（准入/候选版本/diff/one-shot）；`run.py --exp <id>` 恢复已有实验。
2. **先冒烟后全量**：`--limit N`（冒烟规模取 `smoke_limit`） 只在 development；冒烟不进结论、不得晋升。
   冒烟逐题验证两版生成与裁判初判，不执行胜负翻转补测；补测用于非冒烟的开发和固定评测。
3. 唯一改动断言：配置 diff 为空拒绝；触发预检分层取样，至少 1 题输入有差异
   （纯模型改动除外）。
4. 失败处理：单题失败豁免出分母；失败率达到 `max_failure_rate` 整轮 experiment_incomplete——
   **incomplete 不算完赛**（state 保持 running），恢复时进入循环；
   恢复只跳过成功题，失败题必须可重试。失败率按整轮每题最终状态统计。
5. 固定集 **one-shot**：同一候选指纹完赛（adopt/reject）永久拒绝；
   可恢复失败必须恢复原实验。禁止反复刷固定集。

## §3 晋升与门槛

1. 晋升统一走 `promote` 校验（命令入口 `promote.py`，分支调度器自动调用）：
   校验实验结论 → 切指针（候选版本已存在，无拷贝）。以下为单线流程；分支指针规则见 §6。
   新实验冻结 `gate_schema=2`，分三层执行：
   - 开发晋级：完整正式样本无失败，全部初测分歧完成双方各两轮独立补验，**确认净胜 > 0** → iteration 指针 = 候选版本。
   - 固定准入：最新 iteration 与当前 production 在同一开发集、同一评分条件下**直接比较**，
     确认净胜达到 `ceil(fixed_entry_min_net_win_rate × 题数)`（现为 1%，1,000 题需 +10）才读取固定答案、构建验证包或启动固定评测。
   - 固定采用：保留原双条件，生成器识别数严格下降（Judge 严格增加），且确认净胜达到
     `ceil(formal_min_net_win_rate × 题数)`（现为 1%）→ production 指针 = 候选版本。
   净胜一律用翻转补验确认值（两版最终判定相同记 contested 不计；相反按最终方向计）。
   学习来源隔离、数据和模型指纹核验独立于数值门槛，未通过不得晋级。
2. 正式失败：生产指针不动；开发指针保留。
3. 冒烟、过期实验（指针已前进）、非通过结论：一律拒绝晋升。
4. 不累加历次增量净胜；A→B 与 B→C 不能代替 A→C。单线用 `run.py --against-production`
   或 `evaluate_judge.py compare --against-production` 比较锁定的最新开发版与生产版，禁止同时改候选。
   完整同条件结果直接复用，即使收益不足也不重新抽结果；否则只补这个直接开发对比。
   净胜为正但未达固定准入时保留开发版继续迭代，不消耗固定题。
5. 历史实验沿用 spec 中冻结的旧门槛和原 verdict，不回写新结论；可另附新门槛数值解读。

## §4 Judge 口径（与生成器流程完全同构）

1. **双指针**：production_judge（量尺，评生成器实验用它）/ iteration_judge（开发）。
   生成器实验的评判 Judge 始终是 production_judge。
2. **开发轮**：候选 = 新 Judge 版本（换模型/提示词，提示词随版本快照冻结），与
   iteration_judge 在**校准包**（当前生产基线生成的 AI 回复、按聊天类型分层抽样、
   空包拒绝）上逐题配对：每题两版各自判定，识别数 + 配对净胜喂给与生成器**同一个**
   decide()（同门槛比率）。净胜达标 → promote.py judge 切 iteration_judge。
3. **固定轮**：候选 = iteration_judge 锁定快照（禁止 override），与 production_judge
   在**验证包**（fixed 分层抽样，代码强制校验包名含 validation）上比较，**one-shot 同生成器语义**；双条件
   （识别数严格更多且确认净胜达标）→ 切 production_judge。
4. 默认 `pairwise_llm` 的 both_human 是弃权（不记识别成功）。要求初始化对齐来源部署的
   实例使用 `corrected_pairwise`：沿用来源已采用的 Codex 模型、推理参数、提示词、
   参考资料和冻结 LR 校正器。先做 A/B 判断，再提取特征；校正器与初判不同且置信度达到
   来源配置阈值才改判。仍是同一道题的配对盲测；生成器升级不触发重训。
   用户明确授权的 LR 重训实验可例外执行：冻结原训练样本、特征定义和训练参数，禁止用评测调参。
   比较方案按实验冻结，分歧仍做独立补测。schema 2 的“熟悉对象后续聊天”允许同一聊天对象出现在
   学习和开发材料中，但学习须早于规定截止时间，完整评测片段及未来信息不得进入学习材料。
   来源未知或不符合当前隔离规则的开发对比不得用于晋升；旧 schema 1 保留整聊天隔离口径。
   导入与后续快照必须保留整套资产，不得回退全局默认裁判。历史实验保留原 Judge 引用。
5. 断代：Judge/数据/生产基线任一变更，历史识别率禁止跨版本比较；后台按版本分组。

## §5 审计权限

1. 固定实验的逐题详情（含真人答案）不回开发流程：后台不渲染、不给链接；
   server 对 private/experiments/fixed_test-* 的 cases.jsonl 一律 403。开发实验无此限制。
2. 实验产物只有三样事实：spec（输入快照）/ cases.jsonl（逐题证据）/ state（进度与结论）；
   页面与账单从它们生成，无结果副本。
3. 汇报纪律：数字精确（分子/分母/百分比）；判断对象写明；未运行写"未运行"；
   用户显式覆盖必须标注。

## §6 多分支异步迭代

1. **显式提交后调度**：`scripts/iterate_branches.py submit` 冻结提案，`run` 启用调度与自动推全。
   只管理已提交的分支，不接管原单线实验。每个分支基于当前 production 提交单一改动，
   自己保存提案、轮次及候选；不争抢共享 iteration 指针。
2. **逐轮验收**：2 题冒烟无失败 → development 确认净胜为正 → 分支接受新开发版 →
   最新候选对当前生产的直接开发对比达到 §3 固定准入 → 同一候选 fixed_test 通过 → 推全。
   固定准入不足时记录 `development_accepted`；再次提交该分支基于已接受的开发版继续改进。
   完整提案仍保留相对生产基线的累计改动，供新全量后的三方合并使用。
   配对评分、补测确认、失败分母、准入与固定集 one-shot 沿用原协议。
   Judge 开发用 calibration 包；提交时仅冻结已有 validation 包的引用和指纹，
   固定准入通过后才解析其题目、核验来源并按需重建。
3. **并行执行，串行推全**：模型调用在独立进程中运行。创建版本、冻结实验和采用指针在实例锁内完成；
   推全核对 data / production_gen / production_judge 三者，过期结果不得覆盖新全量。
   生产指针与采用凭证一起原子写入，崩溃后可恢复；单个实验不允许重复运行。
4. **新全量上重测**：其他分支三方合并“原基线、分支提案、当前全量”，只重放分支自身的改动。
   新一轮重新冒烟、开发、固定验收；旧实验快照和结果保留，已在运行的旧轮次可完成但不得直接推全。
   同字段或同资产内容冲突只阻塞该分支，需要提交解决冲突的新提案。
5. **冻结样本**：生成器沿用同一数据版本；Judge 的生产生成器变化时，按原包相同题目、顺序、
   上下文和真人回复重建 AI 回复，成功生成可断点复用。数据版本改变时阻塞并要求新提案，禁止自动换样本。
   同一候选不能因换分支、来源元信息或新评分基线而重新刷固定集；新轮次仍受 one-shot 限制。
6. **适用边界**：当前支持本机多个配置/提示词/冻结资产版本；全量指项目 production 指针。
   不包含线上分流、灰度发布、自动提出研究方向或不同运行时代码的工作区隔离。
   操作与恢复见 [ASYNC-ITERATION.md](ASYNC-ITERATION.md)。
