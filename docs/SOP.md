# digital-human 对抗迭代 SOP（唯一权威流程）

状态：现行。本文只规定**关键约束和合法步骤**；文件格式、状态机、校验细节见
`docs/IMPLEMENTATION.md`，行为约定见测试。本文未覆盖的情况：**停止执行并询问**。

## 总原则

0. **实例隔离**：每个数字人（如 example-agent / example-operator）是独立实例
   `instances/<名字>/`，版本、指针、实验、池完全隔离；机制层与超参全局共享。
   切换：`--instance <名字>` 或环境变量 `DH_INSTANCE`（默认 `default`）。
   实例内环境分离 = 生产/开发双指针（§3）；测试入口 = 冒烟 + 开发实验。

1. 唯一优化目标：Judge 盲测识别率（越低越像人）；其他质量维度暂不进指标。
2. **每份状态只有一个权威位置**：版本内容（不可变目录，创建后 chmod 只读，代码强制）、
   指针（pointers.json 五个字段）、实验状态（experiments/<id>/state.json）。禁止手工编辑。
3. 交替冻结：改生成器冻结 Judge，改 Judge 冻结生成器（以指针为准）。
4. 每轮唯一改动：候选 = 基线 + 一个 feature；改动描述必须可证伪。
5. 超参（`config/settings.yaml`）与版本配置分离；前者改动 = 协议变更。
6. **先划分数据，再学习数据特征**（split-first）。

## §1 数据与版本

1. **三分区**（bootstrap 按会话整块切出，seed 固定）：fixed 只评测、禁一切学习训练；
   dev 是开发材料（A/B 评测 + Judge 校准包）；train 供人格/场景/few-shot 池。
2. **版本即目录、创建后只读**：数据版本（切分+池+manifest）、生成器版本（行为配置+
   persona/场景自包含快照）、Judge 版本（配对盲测配置）。候选创建即得普通版本号，
   晋升只切指针。
3. 数据变更 = bootstrap 新建数据版本；`--adopt` 才切换指针并重建快照版本。
   旧版本原地保留，历史实验可复现。
4. few-shot 池小于 settings 的 `evaluation.pool_min_total` 禁止正式迭代；池审批（approved + 内容 hash）运行时强制。
5. **检索策略冻结**：只保留已验证的一条（处境匹配 + 词项 + 最新一句形式偏好仅私聊），
   来源过滤/逐题排除/预算控制保留；再引入新策略须先按 §2 开发集验证。

## §2 实验与恢复（唯一入口 `run.py`）

1. 主线五步：**准备数据 → 创建候选 → 开发盲测 → 固定测试 → 晋升**。
   新建实验自动完成预检（准入/候选版本/diff/one-shot）；`run.py --exp <id>` 恢复已有实验。
2. **先冒烟后全量**：`--limit N`（冒烟规模取 `smoke_limit`） 只在 development；冒烟不进结论、不得晋升。
   冒烟逐题验证两版生成与裁判初判，不执行胜负翻转补测；补测用于非冒烟的开发和固定评测。
3. 唯一改动断言：配置 diff 为空拒绝；触发预检分层取样，至少 1 题输入有差异
   （纯模型改动除外）。
4. 失败处理：单题失败豁免出分母；失败率达到 `max_failure_rate` 整轮 experiment_incomplete——
   **incomplete 不算完赛**（state 保持 running），恢复时进入循环；
   恢复只跳过成功题，失败题必须可重试。失败率按整轮每题最终状态统计。
5. 固定集 **one-shot**：同一候选指纹完赛（adopt/reject）永久拒绝；
   可恢复失败必须恢复原实验。禁止反复刷固定集。

## §3 晋升与门槛

1. 晋升唯一入口 `promote.py`：校验实验结论 → 切指针（候选版本已存在，无拷贝）。
   开发实验净胜达到 `dev_min_net_win`（settings）→ iteration 指针 = 候选版本；
   固定实验**双条件**（识别数严格下降且确认净胜达到 `formal_min_net_win`）→ production 指针 = 候选版本。
   净胜一律用翻转补验确认值（两版判定相同记 contested 不计；相反按最终方向计）。
2. 正式失败：生产指针不动；开发指针保留。
3. 冒烟、过期实验（指针已前进）、非通过结论：一律拒绝晋升。

## §4 Judge 口径（与生成器流程完全同构）

1. **双指针**：production_judge（量尺，评生成器实验用它）/ iteration_judge（开发）。
   生成器实验的评判 Judge 始终是 production_judge。
2. **开发轮**：候选 = 新 Judge 版本（换模型/提示词，提示词随版本快照冻结），与
   iteration_judge 在**校准包**（当前生产基线生成的 AI 回复、按聊天类型分层抽样、
   空包拒绝）上逐题配对：每题两版各自判定，识别数 + 配对净胜喂给与生成器**同一个**
   decide()（同门槛比率）。净胜达标 → promote.py judge 切 iteration_judge。
3. **固定轮**：候选 = iteration_judge 锁定快照（禁止 override），与 production_judge
   在**验证包**（fixed 分层抽样，代码强制校验包名含 validation）上比较，**one-shot 同生成器语义**；双条件
   （识别数严格更多且确认净胜达标）→ 切 production_judge。
4. 默认 `pairwise_llm` 的 both_human 是弃权（不记识别成功）。要求初始化对齐 RPA 的
   实例使用 `rpa_corrected_pairwise`：沿用 RPA 已采用的 Codex 模型、推理参数、提示词、
   参考资料和冻结 LR 校正器。先做 A/B 判断，再提取特征；校正器与初判不同且置信度达到
   来源配置阈值才改判。仍是同一道题的配对盲测；本项目不训练校正器，生成器升级不触发重训。
   导入与后续快照必须保留整套资产，不得回退全局默认裁判。历史实验保留原 Judge 引用。
5. 断代：Judge/数据/生产基线任一变更，历史识别率禁止跨版本比较；后台按版本分组。

## §5 审计权限

1. 固定实验的逐题详情（含真人答案）不回开发流程：后台不渲染、不给链接；
   server 对 private/experiments/fixed_test-* 的 cases.jsonl 一律 403。开发实验无此限制。
2. 实验产物只有三样事实：spec（输入快照）/ cases.jsonl（逐题证据）/ state（进度与结论）；
   页面与账单从它们生成，无结果副本。
3. 汇报纪律：数字精确（分子/分母/百分比）；判断对象写明；未运行写"未运行"；
   用户显式覆盖必须标注。
