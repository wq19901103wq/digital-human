# 数据、训练、检索与评测边界整理

日期：2026-09-14。状态：原设计记录；现行实现以 SOP、DATA_CONTRACT 和下方实施说明为准。

更新：用户已授权执行，schema 2 的实现与验证进展见 [DATA_BOUNDARIES_IMPLEMENTATION.md](DATA_BOUNDARIES_IMPLEMENTATION.md)。下文保留原设计；不将方案或数据准备当成模型验收。

以下记录最初的方案范围；后续实施新增数据和预检任务，保留了原有模型基线、指针和历史实验。

## 1. 需要解决的根因

现在一个 `d` 同时承载评测题、示例池、人格和场景；“训练”又同时指材料提炼、提示词优化和 LR 拟合。因此换数据会带出新的 `g`，而训练来源、测试边界和基线身份难以对应。

新的划分只回答两个相互独立的问题：

1. **时间可见性：**生成这一题时，哪些历史内容已经可知？
2. **使用目的：**哪些样本被用于学习、选择候选，哪些被保留用于验收？

一条历史回复可以是某次早期评测的目标，随后成为较晚题目的可检索历史。这不意味着可以把它加入本轮模型拟合，或反过来用于重新优化早期题目。

已经明确的目标：两类场景都覆盖，以熟悉的人和群的后续聊天为主；示例候选库允许包含全量可信历史，逐题按时间筛选。

尚属建议的参数：熟悉/首次接触按 80%/20% 汇总；沿用群聊/私聊 75%/25%。比例、正式时间边界和样本数量需要由可用数据和实际使用目标确定，本方案没有应用这些数值。

## 2. 数据只存一份，按用途保存样本清单

保留一份不可变的原始历史快照和规范化样本索引。以下集合是带来源、时间和哈希的视图，不要求复制成多套彼此割裂的聊天库。

| 名称 | 内容及用途 | 明确边界 |
| --- | --- | --- |
| 历史语料 | 去重后的可信真人消息、身份、顺序、时间、来源 | 不把未经核实的机器人输出当真人材料；不包含模型权重或提示词产物 |
| 示例候选库 | 从全量历史提取的完整“上下文→真人回复” | 是否能用于某一题由时间和来源检查决定，不由 train/dev/test 标签决定 |
| Gen 学习材料 | 提炼人格、语气和场景的历史；以后如微调，也记录微调样本 | 保存材料清单与最晚信息时间；当前没有大模型微调 |
| Gen 优化题 | 用于尝试提示词、模型、参数或检索策略的题 | 允许反复看答案和 Judge 反馈；成绩是优化过程结果 |
| Judge 训练题 | 上下文、真人回复、冻结 Gen 生成的 AI 回复、随机 A/B 标签 | 用于拟合 LR；记录 AI 来源、特征模型和训练配方；不混入验收目标 |
| 开发验证题 | Gen/Judge 候选比较、模型及阈值选择 | 与拟合及 Gen 优化目标按完整片段隔离；反复查看后属于选择材料，不能声称是最终独立测试 |
| 验收题 | 候选与比较规则锁定后的一批新题 | 不用于人格提炼、优化、拟合、选阈值或失败后针对性修补再刷同一批 |

Gen 学习材料、Gen 优化题和 Judge 训练题可以来自同一批早期历史，重叠要显式记录，不要求三者按联系人互斥。开发和验收的目标片段不能同时出现在这些学习清单中。

“同一联系人出现于多个用途”合法；“同一目标答案或与它连在一起的回复片段既用于学习又宣称独立验收”不合法。按稳定消息 ID、完整片段和实际内容去重检查，不能只比较重新生成的 case_id，也不能把常见短句相同一律当作泄漏。

## 3. 示例候选库使用全量历史，实际可用集合随题目变化

对每道题保存 `input_cutoff`：该次待回复输入已经到达、尚未生成答案的位置。不能使用真人目标答案的发送时间代替它。

候选示例必须同时满足：

- 来源已核实为真人历史；来源不明或时间边界不全的示例暂不进入正式召回。
- 示例所有上下文、所有真人回复都已在 `input_cutoff` 前发生；检查最后一条消息，不能只检查第一条回复的 timestamp。
- 用于检索的摘要、处境标签等也只由该示例及当时可见的资料生成。不能以未来对话为材料生成标签，再只过滤示例正文。
- 不包含本题目标消息、被切开的目标连续回复，或因重复导出产生的同一目标副本。共享部分已知上下文不自动构成泄漏。
- 同一秒的消息使用可靠原始顺序判断；无法确定先后时保守排除。跨聊天也用统一时间标准，不能只检查本聊天。

先按这些条件确定可用候选，再排序与取 top-k。检索规则不同的两个 Gen 可以选不同示例，但必须遵守同一历史可见范围；实验保存实际召回 ID 和哈希。

例如：题目输入于 10:00 到达，真人目标回复于 10:03 发出。完整结束于 09:58 的示例可以使用；从 09:59 开始但最后一条回复在 10:01 的示例不能使用；10:03 的目标答案不能使用。到 11:00 的另一道题时，10:03 的真人回复可以作为已发生的历史。

这里评测的是**在真实历史上下文中逐题续写**。每题使用既有真人历史，不把本轮候选生成的回复写回真人示例库。若以后评测模型自己连续聊很多轮，需要另设协议，不能混用这两种分数。

固定验收答案由回放服务按事件时间开放给后续题的检索过程；开发者页面和调参流程不能因此批量读取封存答案。必须把“按时间提供真实历史”与“查看答案改模型”区分开。

## 4. 静态学习和动态检索采用不同边界

推荐采用全局时间窗口，按完整对话片段划分：

```text
较早历史 A                  中间窗口 B                   更晚窗口 C
Gen 材料与优化              开发验证、选择候选            锁定候选后验收
Judge 拟合                  选择模型/阈值                不拟合、不调参
-------------------------->----------------------------> 时间
每道题的示例：全量候选库中，截至该题输入时已经发生的可信内容
```

这不是必须按 50%/25%/25% 消息数硬切。先检查日期分布、群聊/私聊容量、完整片段边界和首次接触样本数量，再冻结窗口及抽样清单；不能为了凑数量查看模型结果后换题。

正式验收模型及提示词的学习来源、参考资料和选择反馈都必须在验收窗口前；同一批验收中参数、提示词、阈值和规则保持冻结。开发验证用于选择，反复查看带来的选择偏差应如实标记。

Judge 训练用 AI 选项可以由冻结的 Gen 对早期训练题生成；这是构建训练对，不宣称为严格的历史上线回测。必须记录 Gen 的学习范围，并禁止把目标真人回复及其副本直接送入生成输入。要将某批生成结果作为时间回放成绩，则该批输入的提示词、画像、记忆等也必须通过时间来源检查。

只有示例历史随题目时间增长。模型拟合与提示词再提炼属于新版本，不能在同一轮里静默更新。需要滚动训练时，另建时间窗口和模型快照，每个版本只评其学习边界之后的新题。

当前按“每个联系人各自 50%/75%”的切法不等同于全局时间隔离：甲联系人的训练日期可能晚于乙联系人的测试日期。共享的 Judge 权重、人格和场景仍可能带入未来信息；逐题过滤示例无法修复这个问题。

验收批次固定，但不能永久作为独立终测反复用于版本选择。若已依据某批结果调整候选，该批后续只能标为历史基准；下一轮独立验收使用未反馈过的新批次，并在同批上重跑当前基线与候选。多候选同时比较须事先冻结选择规则和试验数量。

## 5. 熟悉对象和首次接触同时覆盖

熟悉程度是题目在发生时的状态，不是数据集的永久分区。

- **熟悉对象：**同一私聊或群在题目前已有真实互动记录。记录历史交互次数、距离上次互动的时间、可用示例数，不要求该聊天被抽入 Judge 的 1,200 道拟合题才算熟悉。
- **首次接触：**来源覆盖足够完整，且题目前没有该聊天的互动历史。只因抽样漏掉历史、或导出从中途开始，不能标成真实首次接触。
- 同一聊天可以从首次接触进入熟悉状态。若已有少量历史但不足以称为熟悉，显示历史量，依据预先冻结的阈值归入相应层级。
- “没有该聊天历史”不等于“从未见过这个人”：同一个人可能出现在别的群。页面和报告使用“首次接触该聊天”这一可验证口径。

自然首次接触样本不足时，如需额外测完全未见对象，可建立单独的整聊天留出集合。那是另一个评测条件，需同时屏蔽其检索、画像和学习来源，不能偷偷混入正常时间回放的总分。

建议主报告分别显示熟悉群聊、熟悉私聊、首次接触群聊、首次接触私聊四项。每项展示有效题数、失败数、来源聊天数和配对净胜；按预先冻结的权重汇总。单聊天题数上限与样本相关性要纳入统计协议，不能把同群相邻题当作完全独立证据。

初始建议的每 1,000 题构成为 600/200/150/50，但尚未验证自然首次接触样本能否满足这些配额。容量不足时明确报告，调整窗口或权重后创建新评测清单，不临时用熟悉题补齐“陌生”配额。

## 6. Gen 和 Judge 的职责

**Gen 学习与优化：**早期历史形成 persona、scenarios 等资产；优化题用于尝试生成策略。当前没有微调，不能把材料条数写成“模型训练条数”。如果将来微调，再增加权重资产和对应训练清单。

**Judge 拟合：**从训练清单取题，在同一上下文下组成真人/AI 回复对，随机安排 A/B 标签；冻结特征提取器与特征定义，拟合 LR。模型、参数、训练样本和 AI 生成来源分别记录。当前训练规模 1,200、600 群聊/600 私聊是旧配方，不是永久科学约束；是否调整需单独比较，不能夹在本次分区改造中改变。

**Judge 开发验证：**在不用于拟合的题上比较新旧裁判或选择阈值。换特征模型与换训练数据是两个变因，应分别描述；生成器训练对来源改变也要记录。

**Gen 评测：**当前量尺 Judge 冻结，同题比较基线与候选生成器。不能让两臂分别被不同 Judge 评分。

**Judge 评测：**同一批上下文、真人回复和冻结 Gen 产生的 AI 回复对交给两个裁判。若目标是适应多代 Gen，训练/评测包显式记录多个来源及比例；不能只训练或只评一个旧 Gen，却声称对所有生成器都有效。

两套开发验证清单建议分别管理，方便识别谁看过哪些题。若共享清单，须记录共同暴露，不能将一方已反复学习过的结果称为另一方完全独立的验证。

## 7. 版本和当前基线

| 对象 | 对内容负责 | 何时产生新版本 |
| --- | --- | --- |
| 数据 `d` | 历史快照、规范化样本、来源和索引 | 原始内容、清洗或样本构建发生变化 |
| 生成器 `g` | 模型、参数、提示词、检索策略及实现依赖 | 实际可执行的生成行为内容变化 |
| Judge `j` | 模型、提示词、参考资料、特征定义、权重和判定参数 | 实际判别内容变化 |
| 评测清单与协议 | 题目 ID/顺序、用途、时间窗口、可见规则、分层权重、采用门槛 | 任一条件变化就保存新清单/协议及哈希，不冒充原评测 |
| 训练记录/实验记录 | 来源清单、父版本、执行状态、输入输出、采用证据 | 每次执行都有自己的记录，不靠新增模型编号表示“又跑了一次” |

评测清单和协议是可点开的独立资产，初期可用名字和内容哈希，不强制再增加多套用户需要记忆的序号。

`g` 的行为指纹不含当前检索语料版本。生成器资产的**构建来源**仍保存为独立 provenance：用了哪个数据、哪些材料、最晚信息时间。不能简单删除旧 `data_version` 字段后丢失来源。

只增加历史或改变题单，沿用行为相同的 `g`；纯连接检查保存新实验但复用原 `g`；真正换模型名、参数或提示词时才生成新行为版本。多个构建记录得到完全相同资产时，可指向同一行为版本并分别保存来源记录。

每次实验锁定：`数据 + 题单/协议 + 检索索引及可见规则 + 基线/候选 + 冻结的另一方 + 运行实现`。训练任务额外锁定训练清单、AI 选项、特征和配方。缓存及续跑必须核对完整依赖，不能只比较 case_id。

“当前基线”分成生产组合与开发候选：

- 生产组合包含当前数据、Gen、Judge、可用评测协议；明确链接到采用实验，或标明“导入初始化，尚无本项目验收”。
- 开发实验创建时与当时的开发基线比，正式验收与当时的生产基线比；创建后引用冻结。若指针变化，标为旧基线实验，不能替换其输入或直接覆盖新基线。
- 导入数据不顺带重建并采用 Gen/Judge。数据组合改变后，先在同一新条件下重测当前基线与候选，保留独立的数据采用记录。

## 8. 可审计的最小字段

| 记录 | 需要保存 |
| --- | --- |
| 原始消息 | 稳定 message_id、来源文件及哈希、聊天身份、事件时间、原始顺序、来源可信性 |
| 题目/示例 | context_message_ids、reply_message_ids、完整 source_span、input_cutoff、内容哈希；示例最后可用时间 |
| 用途清单 | 数据引用、用途、目标消息/片段 ID、抽样规则、时间窗口、分层、数量、交叉与重叠审计 |
| 提示词/训练资产 | 所用材料清单、父版本、学习范围、提取/训练实现、内容哈希；来源无法证明时显式标记 |
| 实验/回放 | 固定题单、协议、双方模型、冻结量尺/回复包、逐题可见范围、实际示例、执行实现、状态 |

稳定消息身份不能只用秒级时间戳，也不能依赖在不同子集内重新从零计数的消息位置。旧 ID 保留映射，不回写历史实验。

## 9. 当前实现与目标的差距

整理时生产和开发指针均为 `d-0009 / g-0017 / j-0012`。另有 `d-0010 / g-0018` 的熟悉对象时间划分准备产物，尚未成为生产组合。状态以各自文件为准。

| 现状与代码位置 | 需要调整 |
| --- | --- |
| `bootstrap/partition.py` 先分配整聊天给 fixed/dev，训练取剩余 | 建立按全局时间、完整片段和用途的清单；不再把评测聊天全部历史从示例库删除 |
| `scripts/legacy/prepare_judge_temporal.py` 按联系人单独切时间，池只存 train；TemporalExclusions 仍拒绝非 train | 作为旧方案保留；新方案使用全量候选库及 input_cutoff，并审计静态资产时间；不只删除一个判断条件 |
| `generator/generator.py` 主线只传 exclude_ids，召回异常统一降级为无示例 | 接入统一时间资格检查；来源/时间校验失败必须停止该题，不能绕过检查继续 |
| d-0009 示例只有一个 timestamp，题目没有完整目标范围 | 从原始消息核验并补齐来源和完整边界，创建新数据；不猜测旧 timestamp 代表最后一条回复 |
| `iteration/versions.py` 创建 g 时从 d 复制 persona/scenarios 并绑定 data_version | 提示词产物归 g；构建来源与运行数据分开；行为去重与构建记录分开 |
| `scripts/import_wechat.py` 导入采用会建立 g/j 并切五个指针 | 数据导入、初始化、模型采用分别记录；不把导入编号当效果提升 |
| `iteration/experiment.py` 开发/固定文件名与生成器创建耦合 | 显式引用用途清单及协议；无行为变化的检查复用版本；保留历史读取兼容 |
| Judge 训练资料存在独立任务目录，主数据页不能解释完整血缘 | 清单互相链接；展示训练题、来源 Gen、特征模型、产物和采用状态 |
| `data_guard.py`、缓存、runner、promote 依赖旧组合 | 加入清单、可见规则、来源和实现指纹；检查同条件与过期基线；迁移前不复用不完整旧证据 |

当前旧人格、场景及部分 Judge 资产的来源范围未被完全证明。保留为历史基线及诊断对照，不能通过新字段或重新命名将其认证为未见过验收材料。

## 10. 分步落地和验证

1. 先依据本方案同步正式数据契约和协议，定义消息身份、input_cutoff、用途与基线组合。做只读容量审计，列出可用日期、四类场景及来源缺失项，再确定正式题单和权重。
2. 生成新的不可变数据与用途清单，保留旧目录、指针和实验。来源/边界验证先做少量真实片段，再扩展到全量；这一步不调用模型、不训练、不采用。
3. 实现统一历史资格过滤，接到 Gen、Judge 训练选项生成及评测包构建；建立行为版本和来源记录的分离。先验证接口与兼容性，再通过少量真实调用验证完整输入。
