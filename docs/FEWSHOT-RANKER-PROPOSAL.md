# Few-shot 排序模型方案与特征表

更新：2026-09-20。单示例训练设计已确认，1 万条标签已完成，用户已授权离线排序训练，并在审阅两侧独立抽取与本地 FG 实现后确认继续。当前流水线复用已缓存特征，抽取完成后自动训练；现用选择策略未改变。实时进度和训练指标以输出目录的自动报告为准，线上缓存设计见第 12 节。

## 1. 已确认的设计约束

- 历史示例的特征离线预计算。每个示例独立处理，输入是它自己的完整上文、完整真人回复气泡及当时可用的元数据。
- 当前对话的特征在线只抽取一次，所有候选共享。输入是本次回复前的完整可用上文及当时可用的元数据，不包含待预测的真人回复、生成回复或评测结果。
- 当前上文与候选之间的交叉特征，只通过本地确定性计算获得。大模型不能同时看到当前上文和历史候选，更不能直接输出二者的匹配分。
- 排序输入为：当前上文特征 + 候选自身上文特征 + 候选自身回复/交互特征 + 本地交叉特征。
- 所有模型输入先离散化，每个字段使用 8 维 embedding，无连续数值旁路。
- 对每个候选独立打分；训练比较两个候选的 logit 差，不先做特征差再输入 DNN。
- 训练标签生成时，每次只使用 1 条候选示例，学习单条示例对当前上文的效用；线上逐条打分后可以选择多条。
- 线上及正式端到端评测保持最多 3 条示例、总共 2500 字符的现有预算。固定 Judge、生成模型和其他生成配置，单独检验示例选择效果。

“完整上文”指该样本在预测时确实可见的上下文窗口；不缩成最后一句，也不额外读取整份聊天档案。超出模型输入限制时必须按冻结规则处理并记录窗口，不能静默丢失内容。

## 2. 整体链路

```text
离线：每条合法历史示例
      ├─ 自身上文 + 元数据 → 上文特征
      └─ 自身上文 + 自身完整回复 → 回复/交互特征
                       ↓
                 示例特征缓存

在线：当前完整可用上文 + 元数据
      ├─ 大模型抽取一次 → 当前上文特征 ────────────┐
      └─ 现有召回 → 时间/来源过滤 → 候选及缓存特征 ─┤
                                                ↓
                         逐候选本地计算交叉特征
                                                ↓
                         批量 embedding + DNN 打分
                                                ↓
                   排序、去重、预算筛选 → 最多 3 条
                                                ↓
                              原有生成器生成回复
```

一次请求有 K 个候选时，新增的语义抽取是 1 次当前上文请求，不是 K 次匹配请求。当前上文缓存命中时为 0 次；候选缓存缺失由离线任务补齐，不在排序时逐候选调用大模型。正式比较要求事先完成合法候选池的特征覆盖；服务兜底如需采用原选择器，必须记录原因，不能把兜底结果混作完整排序模型结果。

接口边界拟定为：

```text
extract_context(context_only, metadata_as_of_context) -> ContextFeatures
extract_example(example_context, example_reply, example_metadata) -> ExampleFeatures
cross(ContextFeatures, ExampleFeatures) -> CrossFeatures       # 纯函数，无模型客户端
score(ContextFeatures, ExampleFeatures, CrossFeatures) -> logit
```

候选自身的上文语义使用与当前上文相同的提取定义，而且只看候选上文，不能因看过历史回复而反推“当时想要什么”。候选回复与自身上文的交互质量另行抽取；两种结果离线合并。这样候选上文和当前上文的同名字段含义一致。

## 3. 上文特征表：当前对话与候选自身上文共用

下表的字段在两侧各有一份。代码能可靠获得的值不交给大模型猜；多值语义标签展开为固定枚举的布尔字段，各自 embedding。

| 组别 | 字段/信息 | 提取方式与边界 |
|---|---|---|
| 聊天环境 | `chat_type` 私聊/群聊；`chat_id`；场景 `scene`：工作协作、安排事务、日常闲聊、娱乐、求助、讨论、其他/未知 | 类型与 ID 来自原始元数据；场景从自身上文抽取。地点、线上/线下等环境只有上文明示才填写 |
| 对象身份 | `counterpart_id` 私聊对象；`latest_speaker_id`；`explicit_addressee_id`；`has_explicit_addressee`；`addressee_scope` 本人/他人/多人/未知 | 稳定 ID 来自原始数据；显式 @、引用等可定位对象才设置对象 ID。群 ID、最后说话者、被回复对象分别记录，不能等同 |
| 对象关系 | `relationship` 同事/朋友/家人/其他/未知；`address_register` 熟悉/礼貌/职务/未知 | 仅来自上文或有明确时间来源的关系记录。姓名不能用于猜关系；不能使用未来汇总的人设档案 |
| 参与结构 | `visible_participant_count_bin`、`context_message_count_bin`、`speaker_switch_count_bin`、`last_speaker_run_length_bin`、`has_self_history` | 代码计算；参与人数仅指窗口内实际出现的人数，不伪装成完整群成员数 |
| 发言序列 | 最近 5 条的 `speaker_role_i`、`speaker_id_i`；相邻说话者是否相同；本人最近出现的位置桶 | 代码计算；长上文的整体统计也保留，不仅依赖这 5 条。角色为本人/当前对象/其他/未知 |
| 时间与气泡结构 | `hour_band`、`weekday_or_weekend`、`latest_gap_bin`、`recent_gap_pattern`、`last_speaker_burst_length_bin`、`message_length_pattern` | 仅使用可靠时间戳和原始气泡边界。计数、间隔、长度离散化；没有时间戳就是缺失，不猜输入速度 |
| 当前任务 | `primary_intent` 请求回答、确认、澄清、协调、分享、评价、求助、玩笑、寒暄、结束等；`pending_intent_*` 尚未处理的动作 | 大模型从完整自身上文抽取，区分最新消息动作与尚未解决的前文任务 |
| 话题与阶段 | `topic_domain`；`dialogue_stage` 开场/展开/追问/修正/确认/结束；`topic_shift`；`has_unresolved_question` | 大模型从自身上文抽取；不读取之后实际采取的回复动作 |
| 接话需求 | `needs_direct_answer`、`needs_clarification`、`needs_acknowledgment`、`needs_empathy`、`needs_coordination`、`needs_fact_boundary` | 独立布尔字段，不把所有需求挤成一个主动作 |
| 情绪与语体 | `incoming_tone` 平静/热情/玩笑/调侃/支持/严肃/不耐烦/正式/其他；`emotion_valence`；`emotion_intensity`；`formality`；`urgency` | 大模型从可见表达抽取；强度使用固定等级枚举，缺少证据时未知 |
| 连续性 | `last_self_action`、`last_self_tone`、`self_stance` 支持/反对/中立/未表态；`has_pending_commitment`；`has_correction_or_disagreement` | 只描述上文中本人已经说过或承诺过的内容，不推测后续回答 |
| 可观察表达 | `has_question_mark`、`has_mention`、`has_explicit_name`、`has_emoji`、`has_laughter`、`has_link_or_media_marker`、`is_group_repetition_pattern` | 代码提取。称呼识别依赖当时可用的名称映射；无法可靠解析时记录未知 |
| 信息充分性 | `information_sufficiency` 充分/部分/不足/未知；`referent_ambiguity`；`requires_external_fact` | 大模型只描述上文，不尝试填补缺失事实 |

`chat_id`、`counterpart_id` 等可作为离散身份字段输入，适用于“熟悉对象的后续聊天”；新对象统一进入 OOV。样本 ID、实验 ID、候选 ID、训练标签不作为模型特征。身份表只能由训练输入建立，不能通过扫描开发/固定样本预先建立。

## 4. Few-shot 自身回复与完整交互特征

一个 few-shot 的完整对象是“历史上文 + 当时完整真人回复气泡”，不能只给回复打几个质量分。

| 组别 | 字段/信息 | 来源 |
|---|---|---|
| 回复动作 | `reply_action` 回答、推迟、接受、拒绝、确认、调侃、赞同、反对、追问、澄清、补充、收尾、安慰、评价、纠正、协调等；`secondary_action_*` | 大模型只看该历史示例 |
| 开头怎么接 | `opening_style` 直接答复、先确认、先共情、先称呼、先反问、先调侃、直接补充等 | 只看示例自身上文和回复，描述已经发生的接话 |
| 动作顺序 | `first_bubble_action`、`second_bubble_action`、`last_bubble_action`；`response_structure` 结论后补充/回应后追问/逐点回答/单个反应/其他 | 从原始气泡序列抽取；不存在的第二气泡标记“不适用” |
| 语气与表达 | `reply_tone`、`formality`、`emotion_intensity`、`directness`、`humor_style`、`explanation_level` | 固定枚举/等级；复用 Judge 的可解释定义，单独抽取 |
| 消息节奏 | `bubble_count_bin`、`total_length_bin`、`first_bubble_length_bin`、`last_bubble_length_bin`、`max_bubble_length_bin`、`bubble_length_pattern`、`question_bubble_position` | 代码计算；可区分单短句、多个短句、先短后长、先长后短等 |
| 时间节奏 | `first_reply_delay_bin`、`intra_reply_gap_pattern` | 仅在真实源时间可靠时离线计算；生成器不输出发送时间时，这些只作历史描述，不能宣称已控制实际发送延迟 |
| 称呼与对象 | `has_address`、`address_type` 姓名/昵称/职务/亲属称谓/@/其他；`address_position`；`reply_addressee_id`；`uses_second_person` | @、稳定身份由代码解析；隐含称呼的类型可由大模型识别。识别不出的对象 ID 为未知 |
| 表面风格 | 问号、叹号、省略号、emoji、笑声、语气词、数字、链接、引用、重复字等；`reuses_own_context_phrase` | 能直接计算的均用代码，计数分桶 |
| 交互完成度 | `answers_own_context_request`、`clarifies_own_ambiguity`、`advances_own_coordination`、`acknowledges_own_emotion`、`closes_or_continues` | 大模型可比较该示例自己的上文与回复；不能看到当前待生成对话 |
| 自身连续性 | `own_context_fit`、`own_addressee_fit`、`own_timeline_continuity`、`own_stance_continuity` | 借鉴 Judge，全部限定在历史示例内部；不是“与当前对话匹配度” |
| 示例可迁移性 | `depends_on_unstated_fact`、`unsupported_fact_signal`、`repeats_context_needlessly`、`over_explanation_signal`、`named_entity_density_bin` | 描述示例本身对专有事实的依赖；是否对当前请求有用仍交给排序器学习 |

不把 Judge 的人类/AI概率、正确性标签、当前目标真人回复的风格，作为这些字段的来源。已有 Judge 抽取产物若曾看过当前 A/B 答案，不能直接改名后作为上文特征复用。

## 5. 本地实时交叉特征

交叉函数只接收两侧已经产生的特征与合法元数据；不读取额外聊天记录，也不调用模型。下列均在打分前生成。

| 交叉特征 | 具体计算 |
|---|---|
| 同一私聊对象 | 两侧 `counterpart_id` 已知且相等；未知单独一类 |
| 同一群/聊天 | 两侧 `chat_id` 相等；与“同一回复对象”分开 |
| 同一最新发言者 | 两侧 `latest_speaker_id` 已知且相等 |
| 同一明确回复对象 | 当前 `explicit_addressee_id` 与示例 `reply_addressee_id` 已知且相等 |
| 对象在示例中出现 | 当前明确对象 ID 是否属于示例可见参与者集合 |
| 场景/关系一致 | `chat_type`、`scene`、`relationship`、`topic_domain` 分别做相等判断 |
| 对话阶段一致 | 当前 `dialogue_stage` 与示例上文 `dialogue_stage` 比较 |
| 需求重合 | 两侧 `pending_intent_*` 的交集数、并集数/Jaccard，之后分桶；空集合/缺失单独处理 |
| 主意图组合 | `(当前 primary_intent, 示例上文 primary_intent)` 作为离散类别组合 |
| 需求与回复动作组合 | `(当前 primary_intent, 示例 reply_action)`，以及各个需求布尔值与动作枚举的组合 |
| 需求与接话开头组合 | `(当前 primary_intent, 示例 opening_style)` |
| 情绪与回复语气组合 | `(当前 incoming_tone, 示例 reply_tone)`、`(当前 emotion_intensity, 示例 emotion_intensity)` |
| 称呼匹配 | 当前是否明确指向对象 × 示例是否带称呼；当前称呼语体 × 示例称呼类型 |
| 群聊与对象回应组合 | 当前群聊/@状态 × 示例指向个人/群体的回应方式 |
| 上下文结构差异 | 可见参与人数、说话者切换数、最后说话者连续气泡数的差值，各自分桶 |
| 节奏组合 | `(当前 last_speaker_burst_length_bin, 示例 bubble_count_bin)`、`(当前 message_length_pattern, 示例 bubble_length_pattern)` |
| 语体差异 | 当前与示例上文的正式程度、情绪强度差值分桶；仅对有序等级计算差值 |
| 连续性组合 | 当前本人上一动作/语气 × 示例回复动作/语气；当前是否待澄清 × 示例是否实际澄清 |
| 历史距离 | 当前输入截止时间减示例完整结束时间，分桶；非正值先由资格过滤拦截，不能交给模型决定是否使用 |
| 字面重合 | 当前上文与示例上文的固定分词集合交并比、已明确出现实体的重合数；本地计算后分桶 |

例如：当前是“熟悉同事在群里 @ 本人确认安排”，示例是“同一个人曾询问时间，本人先回‘可以’，再补一句安排”。代码可以产生“同一对象”“同群或异群”“确认需求 × 先确认”“对方一条 × 本人两条”等字段。大模型不负责判断这两个具体对话是否匹配。

类别组合仅保留上表中有明确含义的字段，不做身份 ID × 身份 ID 的全笛卡尔展开。DNN 可以学习输入字段间的关系；这不增加任何联合大模型抽取调用。

## 6. 离散化与模型初始配置

- 布尔值采用真/假/缺失；类别采用固定枚举，并区分未知、不适用、训练未见值。
- 身份类别只在训练集建立词表；开发和固定轮不扩表、不更新 embedding。
- 计数可用 `0 / 1 / 2 / 3 / 4–5 / 6–10 / 11+`；长度可用 `0 / 1–4 / 5–8 / 9–16 / 17–32 / 33–64 / 65–128 / 129+`。按字段合理选用，规则冻结在预处理版本内。
- 历史距离可用 `<1天 / 1–7天 / 8–30天 / 31–90天 / 91–365天 / >365天`；短消息间隔另用秒/分钟桶。可用性过滤仍检查原始精确时间。
- 有序语义强度由抽取时输出固定等级，不依赖扫描评测集拟合分位点。
- 每个字段独立 8 维 embedding，拼接后进入共享 MLP，输出单个 logit。

建议首个配置：`MLP 128 → 64 → 1`，隐藏层 `LayerNorm + SiLU`，dropout `0.1`，AdamW 学习率 `1e-3`、weight decay `1e-4`。训练内验证集早停。先以 LayerNorm 避免线上候选批大小影响预测；BN/无归一化、宽度和正则化可作为后续复用同一特征的配置比较，不在本次方案 Review 前启动。

```text
sA = scorer(current_context, example_A, cross_A)
sB = scorer(current_context, example_B, cross_B)
P(A 更值得选) = sigmoid(sA - sB)
```

同一个 scorer 共用所有参数。线上对候选按分数排序，分数不是已经校准的“生成通过率”。保持固定去重和预算规则，不在首版另外引入模型驱动的 Top3 组合搜索。

## 7. 训练标签与数据隔离

标签要回答“给这个上文使用这个示例，是否让后续生成更像本人”。示例本身是真人回复，不意味着它适合所有上文；不能直接把 Judge 的真人/AI训练标签搬给排序器。

### 7.1 一个目标上文与一个监督样本

目标事件 `q` 是历史上本人即将回复的一个真实时刻。原始记录包含：该时刻的完整可见上文 `Cq`、输入时间边界 `tq`、当时元数据，以及随后完整的本人真实回复 `Hq`。`Hq` 仅供生成效果标注使用，不进入召回、上文特征或排序器输入。

目标事件从既有合法训练时间区选择，兼顾对象、群聊/私聊、上文场景与时间段；不从正式开发/固定样本中借数据。训练目标清单和选取规则先冻结，不按 Judge 的标注结果挑选“好学的题”。首批拟复用 d-0011 的 1000 条生成器优化题作为目标来源，计划 800 个训练上文、200 个训练内验证上文；这是待 Review 的规模上限，具体来源、时间切分及不足处理见 7.5。

一条候选观察的形式是：

```text
Observation = (target_id, candidate_id, condition_ref,
               context_features, example_features, cross_features,
               generation_ref, judgment_ref, z)
```

`target_id`、候选 ID、条件和产物引用用于分组、缓存、追溯；它们不进入神经网络。监督训练的输入由上文、示例、交叉三个特征对象组成；候选对象自身包含其上文与回复特征。每条观察对应只使用该候选一条示例的生成结果。

### 7.2 样本中的 few-shot 从哪里来

首批拟复用 `instances/example-agent/data/d-0011/fewshot_pool.jsonl` 的真实历史示例，由同一历史目录下的 `messages.jsonl` 提供原始消息依据，`purposes.json` 提供冻结时间分区，`report.json` 绑定已核验的池内容。现有池文件有 102376 条记录；这是全池记录数，不是每个目标可用的候选数，须按目标时间和来源过滤。具体文件指纹在实施时登记到训练配方；这里不另建来源不明的示例库，也不直接继承旧 RPA 的训练标签。

每条示例由一段真实聊天构成：**该次回复前的上文 + 本人随后连续发出的完整回复气泡**。复用 `src/generator/history_sources.py` 的来源还原：由 `source_span` 定位聊天及消息区间，核对 `context_message_ids`、`reply_message_ids`、文本、说话人、时间与内容指纹，确保没有从多条真人回复中只截取一条气泡。候选 ID 只是定位符，不能替代这些来源依据。

同一个合法历史示例可以出现在多个目标的候选池里，其自身特征只抽一次；但 `(目标上文, 示例)` 的效果标签分别生成。同一条示例对某个上文有用，不代表对另一个上文也有用。

对每个目标事件回放当时的取例过程：

1. **先过滤资格。** 从历史池取源记录，通过既有来源、时间、答案消息重叠保护。同一对象更早的聊天可以使用；示例从上文到最后一条回复都必须已在 `tq` 前发生，不能只检查示例上文时间。
2. **再召回候选。** 仅用 `Cq` 和当时元数据运行拟在线使用的同一个召回策略。首版建议复用现有两路入口：最近 3 条上文和最后一条消息各取最多 12 条，合并去重后最多 24 条。这里的短窗口只用于召回，排序模型仍使用完整可见上文特征。召回参数、排序及同分处理随配方冻结，不能拿真人答案当查询词。24 是拟采用的上限，不是已产出的样本数。
3. **去重并检查单条预算。** 同一原始片段或相同完整内容只保留一条；单条示例按正式格式完整渲染后超过 2500 字符就排除，不截断回复来凑预算。
4. **选入待标注清单。** 总共拟选最多 8 条：先保留基线选择器在该合法候选池中选出的最多 3 条，均作为普通候选分别标注。剩余候选按冻结召回排序等分为高、中、低三个排名段，再分同对象、不同对象、对象未知三类；轮流从非空分组按固定种子无放回抽取，直到总数达到 8 或池已取完。群聊只有明确可核对的对象 ID 才判“同对象”，同群不能替代同对象。固定分组顺序及种子绑定配方和目标 ID，续跑不能重新抽一批。
5. **冻结后单独标注。** 候选清单冻结后，才逐条进行单示例生成和 Judge 标注。未选中、召回靠后或不同对象都不等于负例。数量不足就使用实际数量；不足两个可比较候选时保留观察，但不生成排序对。

优先在实际在线可召回的候选中学习，不用大量显然无关的全库随机例子制造容易区分的负样本。更多全库探索会改变召回范围，属于后续独立设计。

候选选择不读取 `Hq` 文本或下游标签；答案消息 ID 仅供资格保护排除重叠，不进入召回打分或抽样。所有候选一视同仁地单独评估，目标是否有 3 条可用示例不影响其单条观察的有效性；没有合法候选时记录覆盖缺口。24/8 及分层办法用于本次已获授权的候选准备，排序器训练尚未启动。

每个目标的固定清单保存：时间边界、历史池指纹、召回配方、候选来源/原始排名、分组及入选原因、过滤原因、抽样种子、最终候选 ID 与内容指纹。复用已有统一入口生成这些记录，避免手工维护样本表或另写临时检查脚本。

### 7.3 Label 的具体定义

同一个目标的每条候选各自独立生成；生成器的历史示例输入恰好只有这一条：

```text
generated(q,e) = frozen_generator(Cq, [e])
z(q,e) = 1  当冻结 Judge 在 generated(q,e) 与 Hq 的盲测中将生成回复选为真人
         0  当冻结 Judge 正确识别生成回复
```

`z` 的含义是“该条件下本次生成骗过了当前 Judge”，是生成目标的代理标签；不声称它是真实用户满意度。选项位置按冻结规则盲化，归一化结果时按照实际生成回复所在位置计算 `z`。错误、超时、缺失或无法解析的判别不是 `0`，应重试或保持未标注。

保持生成模型、提示词模板、Judge、单条示例位置、预算、解码配置和抽样编号等条件一致；生成器不额外自动补入其他 few-shot，人设等其他材料也必须符合目标时点。候选的完整内容按固定格式放入，不为了凑满预算添加示例或文本。不同候选的请求内容必然不同，不把“条件一致”说成生成随机性已经消失。

首版拟每个 `(q,e)` 保存一次有效生成/判别，令 `u(q,e)=z(q,e)`，优先复用完全匹配的已存观察，不自动启动多轮补标签。这是有噪声的训练监督。若后续配方采用重复抽样，则在同一目标候选组内使用相同的抽样计划，定义 `u(q,e)=mean(z)`；不得因看到某候选得分高就只为它选择性补样本。原正式开发/固定轮的分歧补验要求保持不变。

同一目标的候选直接按 `u(q,e)` 比较，不需要为每条候选另跑一次基线。这个标签表示使用单条示例时的生成效果，不表示相对零示例的因果增益；正式收益由线上多条选例策略与共同基线的开发对比确定。

### 7.4 从候选标签构造排序对

只在同一个 `q`、同一标注条件与抽样配方内构造候选对：

```text
xA = (features(Cq), features(eA), cross(Cq,eA))
xB = (features(Cq), features(eB), cross(Cq,eB))
yAB = 1  if u(q,eA) > u(q,eB)
      0  if u(q,eA) < u(q,eB)
loss = BCEWithLogits(score(xA) - score(xB), yAB)
```

这里的 A、B 标签来自两次各自只放一条示例的生成；构造排序对不代表把 A、B 同时交给生成器。

相同效果的候选首版不构造有方向的排序对，不靠召回名次、同对象身份或文本相似度决定谁胜。也不把不同上文的成功/失败候选直接配对，因为上文本身的生成难度不同。

纯示意：某目标下候选 A/B/C 的 `z` 为 1/0/1，则 A 优于 B、C 优于 B，A 与 C 不产生方向标签。若某目标所有候选同为 0 或同为 1，保存观察但该目标暂时没有 pairwise 梯度，不能编造差异。

一个目标衍生的排序对共享生成观察，并非相互独立的新目标。训练按目标归一化权重，避免候选较多的目标占据过大权重；不同时添加一个排序对及其完全等价的反向副本来虚增样本数。

训练学习单条示例的效用，线上用同一个 scorer 对所有候选独立打分，再按固定去重和预算规则选择最多 3 条。单条得分高不保证多个示例组合一定最优，因为示例之间可能重复、互补或冲突；实际多条输入的效果由真实 Top3 端到端开发比较检验，不能用训练排序准确率代替正式收益。旧标签只有同为单条输入且完整条件、数据资格匹配时才可复用。若后续需要优化组合本身，应另行设计集合条件模型，不暗中添加联合大模型匹配特征。

### 7.5 数据边界、规模与开销

**原首批规模计划（保留历史依据；当前扩充计划见下）：**

- 目标来源为 `instances/example-agent/data/d-0011/gen_optimization.jsonl`。现有文件和用途清单均记载 1000 条生成器优化题，处于正式开发之前的学习时间区；用途清单记载其中群聊 750、私聊 250。另有 `gen_learning.jsonl` 的 17793 条学习材料，本批不自动扩入。1000 是复用现成优化题的预算选择，不是已证明足够训练的规模。
- 目标按输入时间排序，在目标组层面计划取较早 800 个用于拟合、较晚 200 个用于早停和调参。同一目标的全部候选、标签和排序对必须在同一侧；沿用既有重复消息和跨界片段保护，训练材料须在内部验证边界前完整结束，不随机拆散同题候选。
- 先按现有来源和标签器学习材料边界筛出合法目标，再冻结时间切分。800/200 是来源齐全且全部合格时的计划；去重、边界隔离或候选覆盖造成不足，按实际数披露，不从正式开发/固定题补齐，也不为凑数放宽时间限制。

| 用途 | 计划不同目标上文数 | 每个上文候选数 | 单示例观察数上限 |
|---|---:|---:|---:|
| 排序器拟合 | 800 | 最多 8 | 6400 |
| 训练内时间验证 | 200 | 最多 8 | 1600 |
| 首批合计 | 1000 | 最多 8 | 8000 |

8 条是首批标注预算：最多 3 条基线会选的示例，加上最多 5 条来自召回排名及对象分组的其他示例；兼顾现有选择与替代选择。A/B/C 只是同一目标下不同历史示例的代号，各自形成一条 `(目标上文, 单条示例)` 观察；不是全局固定的三个例子，也不把三条一起放进标签生成请求。

上述 8000 是候选观察数，独立目标数仍最多 1000。按首版二元标签，一个目标 8 条观察最多产生 `4×4=16` 个有方向排序对（4 个成功、4 个失败），全成功或全失败时是 0；这些派生排序对不增加独立数据量。跨目标重复入选的示例复用自身特征，故唯一历史示例数只有清单冻结后才知道，不等于 8000。

正式开发和固定验收继续各用既有 1000 题及原口径，不包含在上述训练观察数中。首批是否足以学习取决于有效比较目标数和时间验证表现，不能仅凭 8000 条观察认定样本已足够。

**当前扩充计划（用户已将目标更正为 10000 条）：** 合并同一数据版本的 `gen_learning` 与 `gen_optimization`，按目标 ID 去重并排除 Judge 训练/参考答案重叠；正式开发和固定题不扩入。目标为 10000 个不同的 `(目标上文, 单条示例)` 观察，每个上文仍最多 8 条，因而至少需要 1250 个不同上文。优先保留原批次有效候选，其余上文按固定种子排序补入，不放宽原历史边界；可用候选不足时报告实际缺口，不重复填充或把派生排序对计入 1 万。先前 10 万条任务停止，已存本地召回断点可按下述入口复用。

扩充后的全部目标统一重新计算约 80/20 的时间分区及边界清理，旧标签随目标迁移到新分区并记录来源。只有目标、示例、生成器、Judge、模型配置和运行条件一致的观察才复用；原标注进程完成后才导入其断点并开始扩充批次，避免并发重复请求。最终报告分别给出准备数量和已标注数量，私聊/群聊构成由实际合法学习材料决定，不沿用原 750/250 配比。

1. 延用“熟悉对象的后续聊天”：按时间区分训练、开发、固定阶段，同一个对象可以跨阶段；不随机把同一个目标上文的不同候选拆到训练与验证两侧。
2. 训练内部也按目标上文的时间划分训练/验证；分组键随目标上文绑定，去重及重叠规则沿用数据保护。训练内验证用于早停，正式开发与固定答案不进入权重学习。
3. 权重、词表、分桶学习参数（若后续采用）、训练标签和历史示例均有来源记录，受既定学习截止时间约束；不能用开发/固定轮的结果做历史成功率输入。
4. 每个目标对应的示例须通过现有来源、时间、答案重叠过滤：示例完整结束时间必须早于目标输入时刻，不能把目标答案收进示例。查缓存也不能绕过过滤。
5. 抽取器只收到白名单输入；当前上文抽取不含真人答案，候选抽取不含当前目标。标签生成阶段可以评价答案，但标签和 Judge 答案特征不能进入抽取器或推理输入。
6. 不使用依靠未来聊天总结的关系档案、人设、统计量或已训练权重。数据来源不明的旧 ranker 不直接继承；符合上述条件的旧原始特征和标签才能按具体键复用。

对单个目标，以上边界具体落实到以下输入位置；这也是新排序训练链路接入时必须遵守的合同：

| 输入位置 | 可使用的内容 | 拦截方式 |
|---|---|---|
| 历史示例的上文和完整回复 | 在目标输入边界前已完整发生的真实片段 | 复用来源还原与 `history.eligible`：任一示例上文或回复消息与目标答案消息 ID 相交即排除；检查最后一条回复时间。相同秒只有同一原始聊天具备已核验顺序证据才可放行；当前来源加载器不提供此证明，按不能证明先后处理 |
| 当前上文 | 截止 `tq` 可见的原始消息及当时元数据 | 以白名单构造抽取、召回与生成输入；含 `Hq` 的完整标注记录不能整体传入。当前题的真人答案只交给标注端 |
| 历史示例附带信息 | 示例自身可证明的信息；关系等信息遵循字段声明的当时时点 | 后来补写的人设、关系总结、成功率、别题答案不能藏在摘要、标签或特征缓存中；来源不全时停止使用对应材料，不让模型猜补 |
| 召回索引及统计 | 合法内容的独立表示，以及符合训练边界的冻结检索参数 | 未来示例先排除再做 TopK；不让未来池的词频、词表或学习到的召回参数参与历史目标排名。逐条独立预计算不等于允许使用未来样本 |
| 标签生成器 | 冻结版本及可追溯的项目学习材料 | 生成器仍受逐题历史边界约束；其输入和历史示例不得包含目标答案或未来材料 |
| 离线标注 Judge | 直接复用当前基线，不重训 | 按用户确认的离线监督口径，排除与 Judge 训练 case 重复、目标答案消息进入 Judge 训练上文/答案或参考例子的目标。仅因 Judge 学习截止时间晚于目标，不阻止标注。Judge 可读取 `Hq` 生成代理标签；该批标签不是对 Judge 泛化能力的独立评测 |
| 排序器权重与预处理器 | 合法训练区的输入、单示例效果标签 | 训练内按目标时间分组验证；正式开发/固定题答案及标签不参与权重、词表、分桶拟合，也不反向加入训练候选材料 |
| 缓存 | 内容、配方相同且对当前目标仍合法的产物 | 先判定当前资格，再查内容与条件指纹；旧实验 ID、命中缓存或旧的核验标记都不能代替来源检查 |

时间边界看的是原始消息发生时间和材料的依据范围，不是离线抽特征任务的运行日期。今天为一条合格的旧示例计算只依赖它自身的特征可以复用；今天用后来聊天总结该示例的对象关系则不可以。正常重复的历史短句如“好的”不因文字恰好相同就等同于当前答案泄漏；要依原始消息来源、时间与既有重复样本规则判断，不能为过滤候选而按 `Hq` 文本相似度挑样本。

若有 `M` 个目标、每个最多 `K=8` 条候选、一次有效抽样，在无缓存时最多需要 `M*K` 次生成及同数量的 Judge 评测任务；每次生成只用 1 条示例，每个 `(q,e)` 的观察只计算一次。Judge 任务内部可能包含特征抽取等多个模型请求，不能把任务数当作实际底层请求数。上文抽取按不同目标计一次，示例抽取按跨所有目标去重后的历史示例计，不按候选配对数重复抽取。

已有相同特征不足以生成新的效果标签：改变 few-shot 就可能改变生成回复。已有原实验结果只有数据分区、目标、单条示例完整内容及位置、全部提示词材料、生成器、Judge、预算、抽样条件都一致才可复用；多条示例生成结果不能直接当成单条示例标签，正式开发/固定结果即使缓存命中，也不能拿来训练。这是首批标签可能有调用开销的原因；标签和特征产出后，小模型调参可以全部本地复用。

最终样本清单分别记录原始目标数、合法目标数、唯一示例数、候选观察数、有效有方向排序对数和时间分区；不把同一上文衍生的多个排序对混报为多道独立聊天样本。

现有保护覆盖历史材料和 Judge 学习来源；新 ranker 的权重、预处理器、标签清单仍需正式接入同一学习来源保护，不能声称本文设计已自动得到现有实现的保护。

## 8. 缓存与可复现记录

| 层级 | 复用依据 |
|---|---|
| 示例特征 | 示例上文/完整回复/元数据的内容指纹 + 抽取字段版本 + 提示词版本 + 模型与配置；绑定原始消息来源 |
| 当前上文特征 | 可见上文/当时元数据/时间边界指纹 + 抽取字段版本 + 提示词版本 + 模型与配置 |
| 交叉特征 | 两侧特征指纹 + 交叉计算版本；计算很轻，按需缓存，不为缓存另造流程 |
| 模型分数 | 两侧特征与交叉指纹 + 预处理版本 + 权重指纹 |
| 训练标签 | 目标（含仅供标注的真人答案指纹）、单条候选完整内容及位置、全部提示词材料、生成器、Judge、数据边界、预算、抽样条件全部一致；答案指纹仅用于缓存身份，不进入模型特征 |

数据集版本变化后先重新判定来源和资格；文本、条件未变的有效抽取可复用，不能仅因实验 ID 相同就复用。也不必仅因实验 ID 不同就重抽。调 DNN 结构、BN、正则、学习率不会重新请求大模型特征；新增语义字段或改变抽取定义，才需要补相应字段。第一批新增特征与缺失训练标签仍可能产生大模型调用，不承诺“重训全程零请求”。

排名记录应保留候选来源、特征版本、过滤原因、分数、选中 ID 和预算占用。正式训练与评测沿用现有统一命令/检查入口，不新增临时验证脚本。

## 10. 可复用的候选准备入口

运行 `scripts/prepare_fewshot_ranker.py`，传入 `--data` 数据目录、`--teacher` 标签器版本目录、`--generator` 生成器版本目录和 `--output` 私有输出目录。此入口只做候选准备和来源边界检查，不请求大模型，不生成标签。

扩充时增加 `--observations 10000 --reuse-inventory <原批次目录>`，写入新的输出目录。`expansion_plan.json` 固定目标数量、优先级和来源；`capacity.json` 记录去重、隔离后的容量上限；`preparation/` 保存可续跑的逐目标召回断点。完成后使用同一套 `inventory.json`、`report.json` 和标注入口。容量上限不等于实际已准备数量。

目标数量调整时先停止旧扩充及其标注队列，使用新输出目录，并增加 `--reuse-preparation <已停止的扩充目录>`。入口校验源计划、冻结输入和逐目标断点后，复用达到新目标所需的确定性前缀；`preparation_reuse.json` 记录来源指纹。仍由原扩充流程完成资格检查、时间分区和精确数量裁切，旧目录不改写；此操作不产生大模型请求，成功标签继续通过标注入口单独导入。

- `manifest.json` 固定来源内容、生成器、标签器与选例配方；条件变化时拒绝覆盖旧产物。
- `targets/` 按目标保存完整上文、单条候选、召回路线及名次、选择原因、原始消息来源。中断后同命令续跑，复用已完成目标。
- `teacher_sources.json` 分别统计标签器学习时间越界、训练样本重复、答案原始消息重叠；时间越界本身不被描述为已经看过答案。
- `progress.json` 记录候选准备进度；完成后 `inventory.json` 固定产物指纹，`report.json` 与 `REPORT.md` 自动汇总目标数、候选数、唯一示例数、上文/回复气泡分布及标签状态。

初始清单按更严格的标签器时间条件记录为未标注；原始清单保持不变。用户随后确认直接复用当前基线 Judge，排除重叠目标，不重训。新标注阶段使用上述离线监督口径，独立保存到 `labeling/`，不能把初始报告的时间拦截数解释为答案重叠数。

运行 `scripts/label_fewshot_ranker.py`，传入 `--inventory` 冻结候选目录、`--data`、`--teacher`、`--generator` 和 `--instance`。默认只筛选、冻结切分并报告；加 `--run --workers 16 --passes 2` 才生成和标注，同命令可续跑。

请求经常超时时，可加 `--min-generation-timeout-seconds 120` 提高生成调用的最低等待时长；更长的原有等待时长保持不变。此参数只影响传输等待，不修改冻结版本、请求体、缓存身份或已有标签；实际等待时长和入口代码指纹另存于 `labeling/transport.json`。

扩充批次自动要求复用计划中绑定的旧批次；显式 `--reuse-inventory` 必须与计划一致。原批次仍在运行时，使用 `--reuse-inventory <原批次目录> --wait-for-reuse --run` 排队等待，随后导入完整标签及仅完成生成的断点，数量写入 `labeling/reuse.json`。生成已成功但判别失败时，只重试判别。

候选仍在准备时可同时加 `--wait-for-preparation`，标注入口先等待清单完成，再等待原标注批次释放锁并复用断点，最后开始剩余标注。等待期间不调用模型，状态写入 `labeling/queue.json`；无需人工等候后再次启动。

- 使用原清单的候选，不重新召回或补齐目标。重叠排除后按目标时间约 80/20 分组，同一时刻不拆开，并排除跨验证边界的训练材料；实际数由报告给出。
- 每个观察只放一个完整历史示例，生成成功立即存盘；Judge 失败重试时复用生成，失败不计作负例。
- `labeling/manifest.json` 绑定来源、版本、模型配置、运行代码、筛选原因及切分；条件改变则拒绝续用。
- `labeling/observations/` 保存生成、判别、标签及轨迹；`report.json` 和 `REPORT.md` 自动汇总实际样本数与标签分布；`pairs.json` 仅从全部候选完成的混合目标产生有方向排序对。
- 这批代理标签只用于后续排序训练；准备标签不启动排序器训练，不改变正式评测或晋级规则。

## 11. 已授权的离线排序训练入口

用户确认开始训练后，使用 `scripts/train_fewshot_ranker.py run --inventory <已完成标签的目录> --output <训练输出目录> --feature-config <抽取配置或Judge配置文件> --feature-cache <共享特征缓存目录> --instance <实例> --workers 16 --passes 3 --background`。同命令续跑复用成功特征；完成后重复运行只返回绑定相同的结果。`status --output <训练输出目录>` 读取进度和指标，不请求模型。

该入口保持已有目标时间分组切分，不重新标注。两侧独立特征按内容、schema、提示词及模型身份缓存；历史示例上文与回复互动分别抽取，目标上文不含目标回复。数值先用固定边界离散化，所有字段使用 8 维 embedding，共享 128→64 的 LayerNorm/SiLU 网络，训练损失在输出 logit 上做差。同一上文的排序对权重总和相等；纯正或纯负上文不产生排序梯度，但纳入最终报告。

仅在训练区内部按时间划分早停集；选定轮数后用全部训练区重新拟合。外层验证不参与早停、词表或调参。输出 `model.json`、`predictions.json`、`report.json` 与 `REPORT.md`，包含 ROC-AUC、PR-AUC（Average Precision）、宏平均组内 AUC、配对准确率、Top1 正样本率、NDCG@1/3，并对比同一候选集上的原召回顺序和随机选择期望。纯负上文不计入 NDCG，Top1 分母包括全部上文；分数未经概率校准。指标只说明对代理标签的离线排序效果，不能代替生成器正式收益评测。本入口不切换现用版本。

其中 `recall_order` 是多路召回合并后的 `union_rank`，并不代表现有选法最终采用的顺序。与现有选法的直接比较统一使用 `scripts/report_fewshot_ranker.py --training-output <训练输出目录>`；可加 `--wait --background` 等待当前训练完成后自动产出。此入口只读取绑定的已有标签和模型预测，不训练、不请求模型，输出 `selection_report.json` 与 `SELECTION_REPORT.md`。

对照选择来自每段上文冻结记录中的 `baseline_ids[0]`，模型在同段上文的已标注候选中取最高分；若原选法首条没有标签，该上文从双方比较中同时排除并记录原因，不能偷偷改用下一条。报告验证 AUC、PR-AUC，以及同上文 Top1 正例率、胜负平、净增加正例选择数和按上文重采样的区间。模型同分按均匀选择的期望计算，纯负上文仍纳入分母。该比较回答单条示例选择质量，不代表线上三条示例组合后的生成收益。

## 12. 后续线上使用与离线缓存

本节为后续接入设计，不代表排序器已上线。本轮先完成既定特征抽取、训练和离线对比，不为线上准备追加全库抽取请求。

### 12.1 候选库预计算与请求链路

对准备开放给召回器的全部合法 few-shot 建立离线特征库，而非只缓存本轮训练命中的示例，也不把所有原始聊天直接变成候选。候选内容包括它自己的完整可见上文、全部回复气泡和当时可用的元数据。沿用本轮兼容的成功语义缓存；新入库或内容变化的示例再增量抽取。

每个示例的自身上文语义、回复语义独立抽取，身份、气泡数量、长度桶、字面 token 集等由代码离线计算，合并成可复用的单侧特征记录。回复逐气泡时间戳缺失时保持 unknown。缓存不绑定某个目标对话，不包含当前目标答案、生成结果或标签。

在线收到请求时：

1. 固定本次可见上文及截止时刻；当前上文语义最多抽取一次，单侧代码特征也只算一次，供所有候选共享。
2. 沿用现有召回方式取得候选，每次按目标截止时刻和来源规则筛选；即使特征缓存命中，也必须要求示例完整回复结束时间严格早于目标截止时刻。
3. 批量读取候选的离线特征；FG 只消费两侧特征及必要的来源时间元数据，执行相等、交集、分桶和组合等本地运算，不再回原文重复分词，不调用大模型。
4. 使用同一套训练编码规则，批量进行 embedding 和 DNN 打分，按分数去重并满足最多 3 条、总共 2500 字符的预算，再交给生成器。

### 12.2 缓存层级与失效规则

| 缓存层 | 标识中必须绑定的内容 | 更新及复用规则 |
|---|---|---|
| 独立语义抽取 | 输入内容、提示词、schema、抽取模型身份及实际请求配置；区分上文和回复任务 | 条件相同直接复用本轮缓存；仅重训或调参排序模型时不重抽语义 |
| 单侧完整特征 | 语义缓存引用、来源/身份/时间元数据、代码特征版本及分桶规则；按实例隔离 | 一条示例算一次；代码规则变化只重算受影响的本地特征，兼容的语义继续复用 |
| 当前上文特征 | 完整可见窗口、身份及时间元数据、抽取与代码特征版本 | 同一窗口可复用，窗口出现新消息或相关条件变化时更新；一次请求内全部候选共享 |
| 编码后的候选字段 ID 或 embedding | 单侧特征指纹、词表版本、排序模型权重版本 | 可作为后续性能优化；更新词表或模型权重时重算，不能复用旧模型的 embedding；原始语义特征仍可复用 |
| 交叉特征与最终分数 | 两侧特征指纹、目标截止时刻、FG/编码版本及排序模型版本（分数） | 默认请求内批量计算；有重复请求收益时再使用有容量限制的缓存，不预计算全量目标×示例组合 |

示例 ID 和实验 ID 只作索引，不能独立决定缓存命中。来源删除、隔离条件变化、内容或时间戳更正时，更新候选资格和对应记录；缓存存在不等于当前请求有权使用该示例。特征定义变化时，对应模型必须使用兼容的特征与词表，不能将新旧字段静默混用。

### 12.3 缺失处理与当前实现边界

离线入库统一去重、按缓存键加锁、成功即保存，只重试失败任务。正式端到端比较开始前完成本批候选池的兼容特征覆盖，避免候选缺失改变实验条件。线上缓存缺失时排队异步补齐，不在请求中为每个候选临时调用大模型；需要回退原选择器时记录回退原因和比例，与完整模型路径分开统计。

当前训练实现已缓存两侧独立语义；单侧代码特征仍在样本组装时计算，字面 token 仍在 FG 中读取原文产生。上述完整单侧特征库及线上批量读缓存属于后续接入工作。本轮保持抽取和模型定义不变，避免破坏已冻结的续跑条件。上线效果仍需使用相同生成器和 Judge 做实际多示例生成对比，离线 AUC 或单示例 Top1 收益不能直接替代该结果。

## 13. 缓存特征挖掘与模型对比

使用 `scripts/train_fewshot_ranker.py compare-features --source <已完成训练目录> --reference <已完成compare-lr目录> --output <新对比目录>`。入口复用冻结样本、标签、两侧独立特征、时间分组切分，以及已完成 DNN/LR 的预测。每个方法单独保存完成记录，重启只拟合未完成的方法；不重新请求大模型。

除聊天 ID、发言人 ID 及其风格交叉外，新增四组假设，通过同一个语义 LR 对照分别消融：

| 特征组 | 具体关系 | 要检验的问题 |
|---|---|---|
| 回应需求 | 待解答、澄清、安慰、协调需求 × 示例首尾动作、直接程度、解释和收尾方式 | 示例是否示范了当前需要的回应方式 |
| 前后承接 | 本人前次行为、语气、立场、承诺、话题阶段 × 示例开场、动作和重复程度 | 选择是否考虑聊天已经进行到哪里 |
| 消息节奏 | 轮换、连发、上文间隔、紧急程度 × 气泡数、首尾长度、结构和问句位置 | 当前对话是否适合示例的表达节奏 |
| 示例适用性 | 时间距离、字面重合、对象/话题/意图相同 × 专名密度、上下文依赖和示例自身完整性 | 表面相似是否足够、示例能否用于另一段对话 |

字段覆盖、类别支持度、在同上文候选之间是否变化，只用训练区统计；不从验证标签生成特征。所有新增值仍是离散类别。身份 ID 代表导出聊天及其局部发言人，不假定为跨群全局人物 ID。缺失的回复时间保持 unknown，不补造历史行为或使用标签统计作为特征。

LR 对比更强的 L2 正则；组合特征同时比较 DNN 与显式交叉网络 DCN，每个字段均为 8 维 embedding，尝试网络宽度、LayerNorm/BatchNorm、dropout 和权重衰减。调参和早停只使用训练区内部的时间切分，选定后用全部训练区重新拟合；外层验证统一报告 AUC、AP、组内 AUC、Hit@1/3/5、原选择器对照和不确定性。全部方法及失败消融都保留，不能只报外层最优值。这是已经使用过的验证集上的开发探索，尚非新独立测试或线上采用结论。

## 14. 缓存特征上的架构比较

使用同一入口 `scripts/train_fewshot_ranker.py compare-models --source <原始完整训练目录> --reference <已完成compare-features目录> --output <新输出目录>`。继续使用原标签、原时间切分和已缓存特征，直接复用参考目录中的 LR/DNN 对照预测，无新增大模型请求。

比较语义交叉 DNN、加入当前聊天 ID × 示例聊天 ID 的 DNN、同样输入的 RankMixer 和 XGBoost。神经模型全部字段离散化后使用 8 维 embedding，分别给候选打分，再优化同上文的正负 logit 差。RankMixer 为小规模稠密实现：当前上文、示例上文、示例回复、交叉字段形成四个 token，经 token permutation、独立 FFN、残差及 LayerNorm 后接 DNN；不包含稀疏 MoE。XGBoost 使用仅在训练区拟合的类别 one-hot，优化相同的组内配对损失，不把 ID 当连续大小。

每个神经架构比较三组网络/归一化/正则配置，XGBoost 比较三种树深度与两组叶子权重/正则的六种组合。调参和停止轮数只根据内部训练时间切分；报告保留各组内部损失以及各架构的统一外层指标。每个架构独立落盘并绑定来源、代码和依赖版本，条件相同时断点复用。

## 15. 正标签的重复观测

使用原标注入口，保留原来的版本参数，增加 `--stability-output <独立目录> --stability-mode regenerate --additional-draws 2 --run --workers 16 --passes 3`。默认覆盖已完成标注批次的所有原正例，每条再生成并评分两次；原标签及训练输出保持不变。报告自动区分训练区和验证区，统计追加两次中保持正例为 0、1、2 次的数量；对应包含原观测后的 1/3、2/3、3/3 次正例。

每次新增观测有独立请求身份，避免误用原观测缓存；同次观测失败重试则复用已成功的生成或判别。`judge` 模式固定原生成回复，仅重新抽取 Judge 特征并评分；`both` 模式分别执行两类实验。两种模式结果分别统计，不能把重新生成导致的变化全部归因于 Judge。

这些统计是“原来被标为正例的样本”的条件保留率，不估算全体标签噪声或原负例中的漏标。三次观测只能初步判断一致性。失败保持未完成状态，不作为负例；重复观测不会自动改标、重训或改变线上版本。

## 16. 已有观测上的分级成对训练

用户确认后，使用 `scripts/train_fewshot_ranker.py compare-grades --source <原始完整训练目录> --reference <已完成compare-models目录> --stability <已完成正例复测目录> --output <新输出目录>`。入口只读取已有样本、特征和复测记录，不新增大模型请求。原负例按用户要求直接作为最低等级，不追加复测；保留实际观测次数，0 级是 0/1，1、2、3 级分别是 1/3、2/3、3/3，不能把它们解释成同等观测次数下的成功概率。

同一上文内按 `3 > 2 > 1 > 0` 组成所有严格有序对，同等级不配对。每个候选先独立得到 logit，再优化高等级与低等级的 logit 差；每个上文的配对权重总和相等。四个既有架构复用各自原来选定的特征、超参数、种子及训练轮数，原二元成对模型直接读取已保存预测；仅改变监督等级，不重新选择最优配置，训练和验证分组保持不变。

自动报告全部验证上文上的 Top1/3/5 Hit@K，分别以等级至少 1、至少 2、等于 3 定义命中；同时报告平均等级、线性等级 NDCG、有序对准确率、仅在正例内部的 `3 > 2 > 1` 准确率及各等级平均排名。同分按均匀选择期望处理，纯零上文仍计入 Hit@K 分母，仅在 NDCG 和无可比较对的配对指标中排除。按上文配对的差值与 bootstrap 区间保存在 `report.json`，`REPORT.md` 自动汇总。

三种正例口径分别展示 ROC-AUC、PR-AUC（AP）、组内 AUC、正例样本数量及比例、有对应正例的上文数量及占比，并同时报告全体上文和仅有对应正例上文两种分母的 Hit@1/3/5。没有对应正例时，条件命中率展示 N/A。各口径的正例率不同，AP 应结合正例率解释；模型前后对比必须在同一口径和同一分母下进行。建议关注至少两次成功和分级排序指标，同时保留宽松、严格口径；这不更改训练等级或采用门槛。

已完成比较使用同一报告入口 `scripts/report_fewshot_ranker.py --training-output <已完成compare-grades目录>`，直接读取封存的统计生成 `THRESHOLD_REPORT.md`，记录来源摘要；不训练、不抽样、不请求大模型，不覆盖已封存的原始报告。后续新比较自动展示相同的完整指标。
