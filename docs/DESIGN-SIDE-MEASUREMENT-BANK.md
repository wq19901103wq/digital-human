# 设计方案：按侧测量库（Side-Measurement Bank）

状态：v7 **PASS**（七轮外部评审通过，无 P0/P1 阻塞；遗留 P2/P3 为实施细化项，见 §12）。日期：2026-09-18。

## 1. 背景与问题证据

对抗迭代中"实验"被建模为一次性测量行为：证据（cases.jsonl）与结论焊死在单个实验
目录里，键为（实验配对，题）。实测浪费三类：

1. **同对重复**：补轮（supplement_missing_rounds）、修 scorer 重计分，都新建完整
   实验重跑 1000 题（实例：judge-development-20260917-174147）。
2. **近亲对比成本**：g-0023 对 g-0019 的准入对比需新实验，而生成侧本就有缓存，
   贵的是整条管线的重来。
3. 根因：judge 对每侧的判定是"该侧 AI 回复 vs 同一道真人回复"的绝对测量
   （提示词为证），测量只依赖（版本, 题, 裁判, 协议），与"和谁配对"无关。
   键挂错在（配对, 题）下，换配对即作废一把还能用的尺。

## 2. 设计前提（不可动摇）

1. **信任模型不变**：cases.jsonl 及其哈希链是唯一权威证据；晋升判决可从冻结
   证据逐题重算（强度不降级）。
2. **统计口径不变**：确认净胜仍是唯一门槛口径；**任何复用不得改变门槛的
   一类/二类错误率**（v2 新增，源于评审 P0-1）。
3. **数据集隔离不变**：测量按题目批次键控；固定批次 one-shot 在批次层面保留。
4. **配对补验独立性不降级**：补投票必须是独立新抽签（按侧测量天然满足）。

## 3. 目标与非目标（v2 修正口径）

目标：
- G1 任意两版本在同批题上的**初测对比**（识别数、逐题胜负）= 零调用查询。
  （v2 注明：前提是两侧在该批题上都有测量；仅用于观察/探索，不作门槛判决。）
- G2 **同对复用**：同一配对（A,C）已跑过的轮次（初测/补验）在任何新实验中
  不重复执行；缺轮只补缺的（并集，非对称差——v2 修正）。
- G3 换 corrector/scorer **重计分** = 从已存特征纯重算（同对，统计性质不变）。
- G4 新实验只跑测量库里不存在的（实验, 侧, 题, 轮）。
- G5 新配对（从未同实验测过的 A,C）的准入对比 = **只花裁判调用**（生成缓存
  命中），不要求也不承诺零调用（v2 修正——见 §10.1 统计验证）。

非目标：
- 不改门槛统计（识别数差 + CI 是否补充门槛，另立项）。
- 不引入新权威存储：测量库可删可重建。
- 不动 one-shot、固定批次分配、来源隔离语义。
- **统计验证完成前，跨实验的单侧票不用于门槛判决**（v2 新增）。

## 4. 总体架构

```
事实层（权威，不变）                派生层（新增）
─────────────────────              ──────────────────────────────
versions/ experiments/<id>/        measurements.sqlite3
  cases.jsonl traces/        ──▶   - runner 在实验 finish 时批量写入
                                   - 可全量重建（幂等回填，统一解析库）
                                   - 每条记录 = (source_exp, source_line) 身份
                                   - gates 判决时回读来源行，重算指纹逐字段比对
gates/promote                      - 只回答：哪些(实验,侧,题,轮)已有？缺哪些？
  只读事实层，逐题重算
```

审计纪律（v5，源于评审 P0-2/P2-2/P1-1/四审 P1）：**银行记录本身不能证明
其内容正确，使用前必须回读来源行重算全部指纹**。对**每一条**将被使用的
测量（不限于重放行）：
1. 从 source_exp/source_line 回读 cases.jsonl 原文行；结合该实验 spec
   （两侧版本、data_ref、dataset_role、judge_ref、协议）解析行内全量核心字段
   ——cases.jsonl 行是**配对结构**（同题两侧判定共存一行），配对侧信息
   即来源于此（四审 P2-1）；
2. 用公共库重算 **side_fp、judge_fp、pair_fp、round_fp**（round_fp 需该行
   所属轮次的 draw_nonce 与 origin 信息，取自来源实验元数据/行内字段），
   与银行记录逐一比对；指纹一致即视为核心字段匹配；
3. 重放行追加：round_fp/draw_nonce 与来源行**逐字一致**（继承校验）；
4. 任何一步不符即拒绝。

**结果字段非权威（v6 新增，五审 P1-2）**：测量库中的 llm_verdict、
corrected_verdict、reply_sha256 等结果字段仅用于查询、展示与预计算；
**任何判决必须从 source_exp 的事实层 cases.jsonl 原文行提取结果**——
审计流程（本节的回读重算）本身就是唯一合法的取值路径，禁止实现层直接
读取测量库结果字段作数。

## 5. 数据模型（v3 修订）

身份键：**(source_exp, source_line, side_fp)**——cases.jsonl 是配对行结构
（同题两侧判定共存一行），**一个来源行对应两条侧测量**，每条侧测量以
（来源实验, 行号, 侧指纹）为唯一身份（v7 修正，六审 P1-1）；与审计回读
逻辑对齐，支持同（侧,题）多份测量共存。

**独立轮次身份与去重（v4 修订，评审 P1-1/P2-1/P2-5）**：
- **每次独立抽签（含初测轮）都由 runner 生成全局唯一 draw_nonce（UUID）**，
  不允许为空（v4 修正 v3 的“初测无 nonce”）。
- `round_fp = sha256(pair_fp + round_kind + draw_nonce)`。nonce 的唯一性保证：
  参数完全相同的不同原始轮次也有不同 round_fp，不会被误并（P1-1）；
  重放副本逐字继承来源行的 round_fp/draw_nonce——同一轮次全程唯一，
  去重不损失独立性。
- **来源归属字段**：`origin_exp, origin_round_no`（该轮次最初产生的实验与
  轮次序号）。一致性约束：同一 round_fp 的所有行必须 origin 相同，否则
  按数据损坏拒绝。代价说明（P2-5）：同参数独立轮次不复用是统计安全的设计
  选择，接受其成本。

```
measurements(
  source_exp, source_line, side_fp,  -- 身份键（一行两测量，见上）
  data_ref, case_id, dataset_role,  -- dataset_role: development/fixed_test/pack:<id>
  side_ref, side_fp,                -- side_fp 见下
  judge_ref, judge_fp,
  pair_fp,                          -- 配对指纹 = sha256(排序后两侧 side_fp + judge_fp
                                    --              + data_ref + dataset_role)
  round_fp,                         -- 独立轮次指纹 = sha256(pair_fp + round_kind
                                    --   + draw_nonce)，重放逐字继承
  round_kind,                       -- 'initial' | 'verify'（合并初测与补验）
  round_no,                         -- 实验内轮次序号（展示用）
  draw_nonce,                       -- 每次独立抽签的全局唯一 UUID（初测轮同样有）
  origin_exp, origin_round_no,      -- 该轮次最初产生的实验与轮次序号（归属验证）
  llm_verdict, corrected_verdict, features_sha256, corrector_fp,
  reply_sha256, prompt_sha256,      -- 生成锚（不再单列 generations 表）
  source_status,                    -- finished / supplement_closed
  created_at,
  UNIQUE(source_exp, source_line, side_fp)
)
-- 索引：(pair_fp, round_fp)、(side_fp, case_id)、(judge_fp, case_id)
--       （支撑 G2 同对轮次查询，避免百万级自连接，评审 P2-1）
-- 约束：UNIQUE(round_fp, case_id, side_fp)（防重复数据破坏去重，四审 P2-8）；
--       同一 round_fp 的所有行 origin 必须相同 —— **入库时批量校验**
--       （与写入同事务，非使用时才发现，四审 P2-4）。
```

指纹必填字段（v2 枚举，源于评审 P1-3）：
- side_fp：generator 版本 + 行为配置哈希 + 温度/采样参数 + 随机种子 +
  检索配置 + data_ref（含数据集内容哈希，评审 P2-2）+ dataset_role。
- judge_fp：服务商 + 完整模型版本 + 温度/max_tokens/停止词 + prompt_sha256 +
  corrector 版本与权重哈希 + feature 定义哈希 + 采样协议（flip 轮数、
  force_reply、位置随机规则）+ 重试策略 + **随机种子/幂等参数**（裁判侧若支持
  固定种子则入指纹；不支持则在异质性监控中标注预期波动范围，评审 P2-4）。
- 监控：相同指纹下 reply_sha256/verdict 分布异质性扫描，发现遗漏字段即报警；
  **漂移超阈值处置**（四审 P2-7）：自动暂停跨期复用 + 报警 + 人工排查，
  恢复需重新标定。
- pair_fp 中重复包含 data_ref/dataset_role（已在 side_fp 内）是**故意的冗余
  交叉校验**（四审 P2-6）：两侧指纹与配对指纹各自独立重算，双重不一致
  才可被发现。

写入纪律（v3，源于评审 P1-2/P2-5 与 P1-1）：实验运行期不写正式库；finish 时
批量事务写入，失败实验整批丢弃；同键内容完全一致则幂等忽略，内容不同则拒绝
并报警（禁止 INSERT OR IGNORE）。回填脚本与 runner 调用同一解析/指纹/入库
公共库。**重放行逐字继承来源行的 round_fp/pair_fp（见上）**。

## 6. 流程改造点

1. **规划前置**：planner 查库 → 只跑缺失（实验,侧,题,轮）；同对历史轮次全部
   命中时，新实验 cases.jsonl 从来源行**重放写出**（统一 JSON 规范化序列化，
   评审 P3-3），spec 记 measurement_replay 来源。
2. **同对补轮/重计分（G2/G3，本设计收益最大且统计安全）**：补缺失补验轮只跑
   缺的题；corrector 变化从 trace 特征重算 corrected_verdict（写新行不覆盖）。
   均不产生 1000 题新实验。**有效配对轮次的两侧必须来自同一次原始抽签**
   （同 round_fp 且同 origin_exp/origin_round_no，v4 新增，评审 P1-1）；
   拼轮（把不同原始轮次的两侧凑成一对）一律禁止。
3. **新配对准入（G5）**：生成调用缓存命中；裁判调用按配对重新执行（保持配对
   统计性质，v2 放弃"零调用"承诺）；执行后该配对入库，后续复用走 G2。
4. **重放与跨实验取票**：仅限同 dataset_role；门槛判决的取票规则见 §7。
5. **固定验收**：仅同实验断点续跑可复用；跨实验固定批次测量禁止复用
   （评审 P2-3）。原因（四审 P2-2 补充）：固定验收承担版本基线标定职能，
   要求严格的同实验上下文与同批次执行环境；跨实验复用会把时间漂移引入
   基线，与固定集的存在目的（无漂移的最终裁决）相悖——这不是与“测量与
   配对无关”矛盾，而是固定批次额外的独立性要求。G1/G2 明确排除固定验收。
6. **dashboard**：实验行显示复用率（命中测量占比）；复用来源可展开查看。

## 7. 取票规则（v7 重写，六审 P2-2/P2-3/P2-5）

**适用场景声明（六审 P2-2）**：本规则服务于测量库查询（G1 探索、planner 编排、
P3 跨实验补票）。**正式门槛判决一律基于实验自身冻结的 cases.jsonl**——
planner 已把同对历史轮次重放进该实验，gates 照常逐题重算，不需要在判决时
从测量库取票。

对比 (A,C) 确认净胜的每道分歧题，有效票**固定为该题冻结协议规定的数量
（现行 = 3 票/侧：初测 + 2 补验；任何数量变更走门槛变更流程，不属于本设计）**：

1. **按 round_fp 去重**：同一独立轮次（含其全部重放副本）只计一次；
2. **先取配对轮次**：同 pair_fp 的配对轮次（两侧来自同一次原始抽签，
   **跨实验同样统计安全**——G2 范畴，六审 P2-5）统一按 created_at 取最早，
   凑够固定数量即止；禁止拼轮（不同原始轮次的两侧凑对一律禁止）；
3. **仍不足才单侧跨实验补票**（v4 明确：仅指单侧复用；同对复用通过重放实现
   不属于此列）（**须统计验证通过后**才允许进入门槛判决，见 §10.1；
   双侧同时补票同属此列，六审 P2-5，方差评估双侧最大、默认从严）：
   按 created_at 取最早凑够即止，禁止按结果挑选；
4. 每票执行 §4 审计流程；使用配对轮次时另验两侧归属同一次原始抽签
   （同 round_fp 且同 origin_exp/origin_round_no，且可在 origin_exp 的
   cases.jsonl/trace 中追溯到该轮次记录，评审 P1-1）；
5. 取票规则、去重结果与选中测量的身份写入编排凭证，全程可复现；
6. 任何“全量票决/变票数”方案均属门槛变更范畴，不在 G2/G3 统计安全范围内。

## 8. 审计与安全

- 回读来源行 + 指纹重算 + 逐字段比对（不是只比哈希）。
- 定期全量校验任务：扫描银行 ↔ 回查来源，**逐字段比对全部参数与结果字段**
  （使用时的审计以指纹重算为准，见 §4；逐字段全量比对待定检执行，
  六审 P2-1），不一致报警；挂入 scripts/check.py。
- 复用白名单由指纹硬约束；泄漏防护：dataset_role 与 data_ref 参与指纹。
- 回滚：删库即回滚；系统退化为今日行为。

## 9. 实施分期（v2 重排）

- **P0 统计验证（新增，阻塞性）**：用历史实验数据量化
  (a) 同实验两侧逐题判定相关系数 ρ 与净胜方差；
  (b) judge 漂移（同 (侧,题) 不同时期重复测量的分布差）。
  产出：跨实验单侧复用的方差膨胀系数；若 >10%，门槛判决维持配对粒度，
  G5 保持"裁判调用付费"，仅 G1/G2/G3 落地。
  **分期依赖（四审 P2-3 明确）**：P0 基于历史数据独立开展，与 P1 并行；
  G2/G3（同对复用）经评审确认统计安全，P2 仅需 P1 完成即可启动；
  P3 的跨实验单侧补票须等 P0 结论。
- **P1 地基**：统一解析/指纹公共库 + 建库 + finish 批量写入 + 回填 +
  校验任务。行为零变化。
- **P2 同对复用**：G2 补轮、G3 重计分、同对重放（灰度：先 judge_eval）。
- **P3 新配对减费**：G5（生成缓存 + 裁判执行）；统计验证通过后再开放 §7.3
  单侧跨实验补票。
- **P4 展示**：dashboard 复用率与来源视图。

## 10. 风险与开放问题（v2 修订）

1. **统计效力（评审 P0-1，最重要）**：配对同测的两侧正相关使净胜方差更小；
   跨实验单侧复用相关性消失，等效门槛变化。P0 阶段量化；必要时补投轮数按
   方差膨胀系数上调，使效力匹配（走门槛变更流程，不静默）。
2. **judge 漂移（六审 P2-4 精确化）**：仅**单侧跨期复用**会把漂移导入差值
   （配对同测的复用对漂移免疫，差值抵消）；漂移处置（§5）只暂停单侧跨期
   复用，同对复用不受影响。银行本身使漂移可测量（同 (侧,题) 跨期重复 =
   漂移探针）；漂移 σ 相对效应量（+10~20/1000）可忽略时才开放跨期门槛复用。
3. **trace 保活期（评审 P2-4）**：G3 依赖 trace 特征；约定至少覆盖一个迭代
   周期，晋升类实验 trace 永久保留；trace 缺失时重计分任务显式失败。
4. **历史格式兼容**：回填需适配历史 cases 格式差异（先格式校验报告）。
5. **SQLite 并发与切换阈值**：单实例单写者（finish 批量 + 文件锁）+ 多读
   是当前形态；触发评估 Postgres 的阈值预先约定：并发写入实例数 > 1，或
   总行数 > 1,000 万，或单次同对轮次查询 P99 > 2s（评审 P3-5）。
6. **双跑验收（评审五.2）**：P2 灰度期，复用结论与原重跑结论不一致时的
   判定标准预先定义（指纹一致下的不一致 = 待查，自动归因到漂移/格式）。

## 11. 验收标准

- §1 的重复场景：补轮/重计分的新调用 = 仅缺失单元；与原整轮重跑逐题一致
  （同指纹）。
- 篡改银行单条字段（保持真哈希）→ 指纹重算比对拒绝（v2 审计强度验证）。
- 删除银行 → 行为退化为今日，无状态损失。
- P0 统计报告给出 ρ、漂移 σ、方差膨胀系数与放行建议。

## 12. 评审记录

- **v1 → v2**（外部 LLM 评审，gpt-5.6 通道，2026-09-18）：P0×3、P1×4 全部
  采纳（统计效力前提、审计指纹重算、身份键、取票规则、批量写入、指纹枚举、
  解析库统一）；P2 采纳 4；P3 全采纳。核心修正：跨实验单侧复用进入门槛

- **v2 → v3**（同通道复审，2026-09-18）：结论 REVISE → 7 项 v1 问题核验
  全部通过、无新矛盾；2 个 P1 阻塞项采纳修订：① 新增 **round_fp 独立轮次
