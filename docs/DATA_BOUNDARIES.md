# 可执行的数据边界

历史池可以保留全部导入历史。检索只返回完整结束于当前题目输入之前的示例，排除目标答案及题目声明的留出对象。相同联系人和群的较早历史可以使用；尚未证明先后顺序的同秒消息不能被当作更早消息。

| 用途 | 时间边界 | 允许用途 |
| --- | --- | --- |
| Gen 学习材料 | 开发开始之前 | 构造人格、提示词和策略 |
| Gen 优化题 | 开发开始之前 | 调整生成策略 |
| Judge 训练题 | 开发开始之前 | 抽取特征、建立类别词表、拟合权重 |
| 开发题 | 开发窗口 | 选择候选、比较当前基线 |
| 固定验收 | 验收窗口 | 单次独立验收，不反馈进训练 |

Gen 与 Judge 的学习材料可明确重叠；两个开发用途也可共享题目，不将其表述成两次独立验证。固定验收批次不得彼此重叠。实际比例、时间、模型配置属于实例；来源重建、时间过滤、用途验证属于框架。

校验依次检查原始消息内容及 ID、完整的上下文与连续真人回复、题目输入时刻、用途清单、实际检索示例、模型请求与响应、特征检查点、完整训练矩阵和重建权重。缓存恢复也经过这些检查。只有 `verified: true`、样本 ID 或内容哈希不足以证明来源。

公开目录用合成数据执行破坏性反例测试：篡改时间、答案、上下文、示例、特征、基线凭证或中间日志，应在请求或采用之前失败。尚未写完的日志尾行可在保存原始字节备份后恢复，中间损坏直接停止。

## 回复样本的时间边界

新建数据默认要求本人首条回复距上文最后一条不超过 10 分钟；连续本人气泡的相邻间隔不超过 2 分钟。超过气泡间隔的后续本人发言不拼进答案，也不能以自己的上一条消息为上文另造回复样本。正常短连发完整保留。上文最多取指定窗口条数，并从窗口内最后一个超过 2 小时的断档之后开始。

这些参数由 `scripts/prepare_history.py` 的 `--response-gap-seconds`、`--reply-gap-seconds`、`--context-gap-seconds` 和 `--max-context` 指定，冻结到每版 `purposes.json`。构建后自动复用 `src/bootstrap/data_quality.py` 做全量来源与时间检查，通过后才完成版本封存；运行时按冻结参数重新验证实际取用片段。旧版保留原协议和结果，不覆盖历史材料。

修复已有版本的切分时用 `--source-data <版本>` 直接复用该版冻结的 `messages.jsonl`；它不能恢复旧导入器漏掉的消息。补全消息类型时用 `--reimport-data <版本>` 从该版清单中逐个核对哈希后重新导入原始导出。两者与 `--exports` 三选一；来源哈希和父数据版本写入新版本，避免导出目录范围或内容变化混入本次修复。

需要检查已有数据时，统一运行 `scripts/check.py --output <新报告路径> data --instance <实例> --data <版本> [<版本> ...]`。输出只含各用途样本数、超时与跨段数量、消息间隔统计和用途隔离结果；不会请求模型、运行评测或切换指针。旧版未记录时间策略时按新默认规则统计问题。

时间规则可以排除明显断档，但不能证明短时间内的每句话都在语义上回复上文，尤其是群聊。检查通过只代表明确列出的来源、身份、时间和隔离约束通过，不等于语义标注绝对正确。修正版数据须单独比较，旧版实验分数不能直接沿用。

完整 `check.py data` 报告绑定消息、示例池、各用途清单、来源清单和校验代码的指纹。数据验收通过后，使用 `scripts/migrate_baseline.py --instance <实例> prepare-data --data <版本> --report <报告路径> --reason <原因>` 保存凭证，再用同入口的 `apply --receipt <凭证ID>` 原子切换数据基线。切换只核对已验收内容的指纹，不重新导入或逐条审计；内容或检查规则变化则旧报告失效。仅导入覆盖检查、覆盖冻结阈值的检查不能用于采用。生成器和 Judge 指针保持原值，凭证不声称其在新数据上已通过兼容性或性能验收；正式实验仍须通过原有学习材料与晋级保护。

## 消息类型与导入完整性

WeFlow 导入保留每一条消息事件，包括引用、图片、语音、视频、表情、红包、转账、文件、名片、位置、链接、合并转发、通话、小程序、视频号和未知类型。引用优先根据引用元信息识别，兼容外层类型被标成表情或其他消息的导出；同时保留被引用消息 ID、原文、发送者和类型。附件元信息保存在事件中，不作为模型输入。

去重使用聊天 ID 与平台消息 ID；不同 ID 的同秒同文消息不得合并。同 ID 内容冲突、文件损坏或非法消息直接报错，不静默跳过。无平台 ID 时用内容指纹与文件内出现序号保留重复事件。平台事件 ID 与元信息参与样本来源指纹，旧缓存不能跨内容变更复用。

媒体可读内容在原始导出中缺失时，上文明确标记消息类型及内容缺失；不会凭空生成图像描述或语音转写。文字答案只接受非空文本或引用消息，连续本人回复中夹有其他类型时整段不作为文字答案，不删掉媒体后再拼接。系统与未知事件切断上下文，避免越过未解析事件串起两段对话。

新导入版本封存前自动逐条核对冻结导出与消息归档，要求遗漏、额外消息及元信息丢失均为零。历史版本可用 `scripts/check.py --output <新报告路径> data --instance <实例> --data <版本> --import-coverage-only` 查看按类型计数的差异。此检查与构建复用同一模块，不请求模型、不切换基线。它证明冻结导出里的事件没有丢失，不证明上游导出已经覆盖微信数据库所有内容。
